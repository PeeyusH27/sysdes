## The core idea: a cell, its neighbours, and a fill order

Think of a spreadsheet. Each cell holds an answer, is computed from cells you already filled, and you fill them in an order that has them ready.

Example: how many right-and-down paths reach a cell? The last move came from above or from the left, so add those two cells:

```js
paths[r][c] = paths[r - 1][c] + paths[r][c - 1];   // the first row and first column are all 1
```

Fill **row by row, left to right** and both neighbours are always done. A 3 × 3 grid:

| 1 | 1 | 1 |
|---|---|---|
| 1 | 2 | 3 |
| 1 | 3 | **6** |

### Two strings: prefixes and the empty row

The state is a **pair of prefixes**: `dp[i][j]` covers the first `i` letters of `a` and the first `j` of `b`. Row 0 and column 0 are the **empty prefix**.

Compare the **last letters**. For the longest common subsequence, equal letters use both (diagonal + 1). Otherwise keep the larger of above and left:

## Step by step: the recipe in two dimensions

The same six steps as 1D, with one more index to get wrong.

<Steps>
  <Step title="Name both indices and the cell in words">
    "`dp[i][j]` = the fewest edits turning the first `i` letters of `a` into the first `j` of `b`."
  </Step>
  <Step title="Size the table and avoid the shared-row trap">
    `Array.from({ length: m + 1 }, () => new Array(n + 1).fill(0))`. Never `fill(new Array(n + 1))`.
  </Step>
  <Step title="Seed row 0 and column 0">
    An empty prefix, no items, a grid's first row.
  </Step>
  <Step title="Write the recurrence from the last decision">
    The last move, the last letters, the last item: each points at one neighbour.
  </Step>
  <Step title="Fill in dependency order">
    Row by row. Interval DPs loop by length.
  </Step>
  <Step title="Read the answer, rebuild it, then compress">
    Usually the far corner `dp[m][n]`. Only then drop to one row.
  </Step>
</Steps>

| Neighbour | Edit it stands for |
|---|---|
| diagonal `dp[i - 1][j - 1]` | **replace** `a`'s last letter with `b`'s |
| above `dp[i - 1][j]` | **delete** `a`'s last letter |
| left `dp[i][j - 1]` | **insert** `b`'s last letter |

## Template 3: knapsack, 0/1 and unbounded

Picture a backpack with a weight limit. Rows are items, columns are capacities. Each cell either **skips** the item (the cell above) or **takes** it (the cell `w` columns back in the row above, plus its value).

<AlgoViz trace={knapsackTable} />

One row is enough, but then the **direction** of the capacity loop decides the problem:

- **0/1, high to low:** `dp[c - w]` still means "without this item".
- **Unbounded, low to high:** `dp[c - w]` already includes this item, so it can be taken again.

## Reconstructing the answer

The table stores values, not choices, but each value came from a neighbour you can find again:

- **LCS:** matching letters mean the diagonal. Otherwise move to the larger of above and left.
- **Knapsack:** if `dp[i][c] !== dp[i - 1][c]`, item `i` was taken. Move to `c - w`. Otherwise move up.

This needs the **full** table.

## Complexity

| Variant | Time | Space |
|---|---|---|
| Grid or two strings | O(m × n) | O(n) with one row |
| Knapsack | O(n × W) | O(W) with one row |
| Interval DP | O(n³) | O(n²) |

O(n × W) depends on the **value** of `W`: fine up to about 10^5, hopeless at 10^12.

## JavaScript you'll use

<JsRef to={["arrays", "gotchas", "recursion"]} />

```js
const dp = Array.from({ length: m + 1 }, () => new Array(n + 1).fill(0)); // m + 1 independent rows
const bad = new Array(m + 1).fill(new Array(n + 1).fill(0));             // ONE row, shared m + 1 times
const grid2 = grid.map((row) => row.slice());                             // copy before writing into the input
let prev = new Array(n + 1).fill(0), cur = new Array(n + 1).fill(0);
[prev, cur] = [cur, prev];                                                // two rows, swapped each iteration
```

The shared-row trap fails silently: `fill(x)` puts the **same** array in every slot, so `dp[1][2] = 5` also sets `dp[0][2]`. `Array.from` builds a fresh row each time.

<Callout kind="warning">

- No extra row and column for prefixes: `dp[-1][j]` throws.
- In a prefix table, the letter for row `i` is `a[i - 1]`.
- 0/1 knapsack with the capacity loop going **up**: items get reused.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="Why must 0/1 knapsack run from high capacity to low with one row?">
    Going down, cells to the left still hold the previous item's row. Going up, they may already include this item, which is unbounded knapsack.
  </FollowUp>
  <FollowUp q="Coin Change II and Combination Sum IV look alike. Why different answers?">
    Coin Change II counts combinations: coins outside, one order. Combination Sum IV counts ordered sequences: amounts outside. For 3 with coins 1 and 2, that is 2 and 3.
  </FollowUp>
  <FollowUp q="How would you print the actual edits between two words?">
    Walk back from `dp[m][n]` in the full table. Each cell names the neighbour it came from: diagonal is replace, above is delete, left is insert.
  </FollowUp>
</FollowUps>
