<TLDR>
A tree is a root plus two smaller trees, so most tree problems are solved by **solving both subtrees and combining the answers at the node**. Answers **return up** (heights, sums) or are **carried down** (running sums, BST bounds); paths that bend keep a **global best**. O(n) time, O(h) stack.
</TLDR>

## When to reach for it

<Callout kind="tip" title="Spot it in the problem statement">

- A **binary tree or BST** whose answer depends on whole subtrees: height, size, balance, mirror image.
- **Root-to-leaf paths**: a path sum, every path.
- The **longest path anywhere** (diameter, maximum path sum): it may bend at any node.
- Where two nodes' paths from the root split (lowest common ancestor).

</Callout>

| Variant | Information flows | The node works |
|---|---|---|
| Return a value up | children → parent | post-order, after both children |
| Carry state down | parent → children, as parameters | pre-order, before the children |
| Global best | return one value, record another | post-order, plus an outer variable |
| BST walk | compare, then one branch only | top-down |
| Explicit stack | an array replaces the call stack | any order |

## The core idea: trust the recursive call

Write `f(node)` for the subtree at `node`, and **assume** `f(node.left)` and `f(node.right)` already work: they are smaller trees, heading for `f(null)`. You write only two things:

- the **base case**: the answer for an empty tree (and for a leaf, if the problem talks about leaves);
- the **combine step**: this node's answer, from the left and right answers.

Right for one node means right for the whole tree, by induction. Each node is entered once (O(n) time), and one call waits per level (O(h) stack, h = height).

The three depth-first orders differ only in **when** the node does its work. For the BST `[8, 3, 10, 1, 6, null, 14]`:

| Order | Work happens | Visits | Use it to |
|---|---|---|---|
| Pre-order | before the children | 8, 3, 1, 6, 10, 14 | pass depth, paths or bounds down; copy a tree |
| In-order | between left and right | 1, 3, 6, 8, 10, 14 | read a BST in sorted order |
| Post-order | after both children | 1, 6, 3, 14, 10, 8 | combine children's answers; delete a tree |

## Step by step

<Steps>
  <Step title="Say what the function returns for one subtree">
    One sentence, like "the height of the subtree at node". If parents can't build on the answer (a diameter), return a helper value and keep the answer outside.
  </Step>
  <Step title="Write the base case">
    `if (node === null) return …`: 0 for sums, `true` for "valid", `-Infinity` for maximums.
  </Step>
  <Step title="Decide what flows down and what flows up">
    Ancestors' info (depth, remaining sum, bounds) goes down as parameters; descendants' info comes back as return values.
  </Step>
  <Step title="Write the combine step">
    Build the answer from `left`, `right` and `node.val`. If it bends through the node, update the global best and return only the arm a parent can extend.
  </Step>
  <Step title="Check the shapes that break trees">
    Empty, one node, skewed (recursion depth n), negative values, one-child nodes.
  </Step>
</Steps>

## Template 3: a global best updated at every node

Some paths **bend**: up one subtree, through a node, down the other. Each path bends at exactly one highest node, so the answer is the best bend over all nodes. But a parent can only extend a **straight** arm, so the helper:

- **record** `leftArm + rightArm` (plus the node's value, for sums) in an outer `best`;
- **return** only the longer arm.

## Template 4: BST bounds and ordering

In a BST, **every** value left of a node is smaller and every value right of it is larger. So:

- **One comparison rules out a whole subtree.** Search, insert and range queries walk one branch: O(h), not O(n).
- **Each node lives inside a range set by all its ancestors.** Going left from v sets the upper bound to v; going right sets the lower bound. The root starts at (-∞, +∞).

That makes validation subtle. In `[5, 4, 6, null, null, 3, 7]` each node suits its parent, yet 3 sits right of 5, where everything must exceed 5. Carry `(low, high)` down, or check that the in-order walk strictly increases.

## Template 5: iterative DFS with an explicit stack

V8 (Node and Chrome) holds roughly 10,000 frames, so a skewed tree of 10^5 nodes overflows it. An array stack does the same job on the heap, and some interviewers ask for it.

- **Pre-order**: pop, visit, push the **right** child, then the left, so the left pops next.
- **In-order**: slide left pushing every node, pop and visit one, then step into its right subtree.
- **Post-order**: pre-order with the pushes swapped (node, right, left), then reverse the output.

## Complexity

| Variant | Time | Extra space |
|---|---|---|
| Recursive DFS, any order | O(n): each node entered once | O(h): O(log n) balanced, O(n) skewed |
| Global best (diameter, path sum) | O(n): one post-order pass | O(h) |
| Recomputing height at every node | O(n²) on a skewed tree | O(h): return heights instead |
| BST search or insert | O(h): one branch | O(1) iterative, O(h) recursive |
| BST range query | O(h + k) for k values in range | O(h) |
| Iterative DFS with a stack | O(n) | O(h) on the heap, no depth limit |

## JavaScript you'll use

<JsRef to={["recursion", "linked-list-tree-nodes", "functions-closures"]} />

```js
const dfs = (node, depth) => {               // nested arrow function: sees outer variables
  if (node === null) return 0;               // base case first, always
  return 1 + Math.max(dfs(node.left, depth + 1), dfs(node.right, depth + 1));
};
let best = -Infinity;                        // a global best lives in the closure, not in a parameter
const isLeaf = !node.left && !node.right;    // a leaf has NO children, not "at least one missing"
[node.left, node.right] = [node.right, node.left]; // swap children in one line
```

Numbers are copied into each call, so keep a running best in an outer `let`. A `path` array is the opposite trap: one shared object.

<Callout kind="warning">

- Treating a node with one child as a leaf. In path sum and minimum depth, a leaf has **both** children null.
- Starting a maximum at `0` when values can be negative: use `-Infinity`, or the root's value.
- Pushing the shared `path` array into the results instead of a copy: every stored path ends up empty.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="Recursive or iterative DFS?">
    Recursive first: shorter and easier to get right. Then name the risk: a skewed tree of 10^5 nodes overflows the stack (V8 has no tail-call elimination), and an explicit stack fixes it.
  </FollowUp>
  <FollowUp q="How does the lowest common ancestor change for a BST, or with parent pointers?">
    In a BST, go left while both values are smaller and right while both are larger; where they split is the answer, in O(h). With parent pointers it is the intersection of two linked lists.
  </FollowUp>
  <FollowUp q="Why isn't the diameter always the path through the root?">
    One subtree can be much deeper and wider, so the longest path may bend deep inside it and never touch the root.
  </FollowUp>
  <FollowUp q="Can you traverse a tree in order with O(1) extra space?">
    Yes, with Morris traversal: thread each node's in-order predecessor back to it and remove the thread on the way through. O(n) time, O(1) space, but the tree is modified while it runs.
  </FollowUp>
  <FollowUp q="When should you switch from DFS to BFS on a tree?">
    For levels or the nearest something: level averages, the right side view, minimum depth. BFS can stop at the first leaf; see [Tree BFS](/dsa/patterns/tree-bfs).
  </FollowUp>
</FollowUps>
