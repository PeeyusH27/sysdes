<TLDR>
A tree is a root plus two smaller trees, so **solve both subtrees, then combine at the node**. Answers **return up** or are **carried down**; paths that bend keep a **global best**. O(n) time, O(h) stack.
</TLDR>

## The core idea: trust the recursive call

<Doodle name="stack" size={150} caption />

Picture a manager with two teams. Ask each team lead for their team's answer, then add your own part. You never ask how the leads got theirs. That is **trusting the recursive call**: assume `f(node.left)` and `f(node.right)` already work. You write only:

- the **base case**: the answer for an empty tree;
- the **combine step**: this node's answer, from the two below.

Each node is entered once (O(n)); one call waits per level (O(h) stack).

The three depth-first orders differ in **when** the node works. For the BST `[8, 3, 10, 1, 6, null, 14]`:

| Order | Work happens | Visits | Use it to |
|---|---|---|---|
| Pre-order | before the children | 8, 3, 1, 6, 10, 14 | pass depth, paths or bounds down; copy a tree |
| In-order | between left and right | 1, 3, 6, 8, 10, 14 | read a BST in sorted order |
| Post-order | after both children | 1, 6, 3, 14, 10, 8 | combine children's answers; delete a tree |

## Step by step

<Steps>
  <Step title="Say what the function returns for one subtree">
    One sentence, like "the height of the subtree at node".
  </Step>
  <Step title="Write the base case">
    `if (node === null) return …`: 0 for sums, `-Infinity` for maximums.
  </Step>
  <Step title="Decide what flows down and what flows up">
    Ancestors' info goes down as parameters; descendants' info comes back as return values.
  </Step>
  <Step title="Write the combine step">
    Build the answer from `left`, `right` and `node.val`.
  </Step>
  <Step title="Check the shapes that break trees">
    Empty, one node, skewed, negative values.
  </Step>
</Steps>

## Template 3: a global best updated at every node

Some paths **bend**: up one subtree, through a node, down the other. The answer is the best bend over all nodes, but a parent can only extend a **straight** arm. So at each node:

- **record** `leftArm + rightArm` in an outer `best`;
- **return** only the longer arm.

<ProblemLink slug="diameter-of-binary-tree" /> uses heights as arms. <ProblemLink slug="binary-tree-maximum-path-sum" /> uses sums, and treats a negative arm as 0.

## Template 4: BST bounds and ordering

In a BST, one comparison rules out a whole subtree: search and insert walk one branch, O(h).

Validation is subtle. In `[5, 4, 6, null, null, 3, 7]` each node suits its parent, yet 3 sits right of 5. Carry `(low, high)` down, or check that the in-order walk strictly increases.

## Template 5: iterative DFS with an explicit stack

An array stack avoids call-stack overflow on very deep trees.

- **Pre-order**: pop, visit, push the **right** child, then the left.
- **In-order**: slide left pushing every node, pop and visit one, then step right.
- **Post-order**: pre-order with the pushes swapped, then reverse the output.

## Complexity

| Variant | Time | Extra space |
|---|---|---|
| Recursive DFS, any order | O(n): each node entered once | O(h): O(log n) balanced, O(n) skewed |
| Global best (diameter, path sum) | O(n): one post-order pass | O(h) |
| Recomputing height at every node | O(n²) on a skewed tree | O(h): return heights instead |
| BST search or insert | O(h): one branch | O(1) iterative, O(h) recursive |
| BST range query | O(h + k) for k values in range | O(h) |
| Iterative DFS with a stack | O(n) | O(h) on the heap, no depth limit |

## JavaScript you'll use

<JsRef to={["recursion", "linked-list-tree-nodes", "functions-closures"]} />

```js
const dfs = (node, depth) => {               // nested arrow function: sees outer variables
  if (node === null) return 0;               // base case first, always
  return 1 + Math.max(dfs(node.left, depth + 1), dfs(node.right, depth + 1));
};
let best = -Infinity;                        // a global best lives in the closure, not in a parameter
const isLeaf = !node.left && !node.right;    // a leaf has NO children, not "at least one missing"
[node.left, node.right] = [node.right, node.left]; // swap children in one line
```

<Callout kind="warning">

- Treating a one-child node as a leaf. A leaf has **both** children null.
- Starting a maximum at `0` when values can be negative: use `-Infinity`.
- Pushing the shared `path` array into the results instead of a copy.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="Recursive or iterative DFS?">
    Recursive first. Then name the risk: a skewed tree of 10^5 nodes overflows the stack. An explicit stack fixes it.
  </FollowUp>
  <FollowUp q="How does the lowest common ancestor change for a BST?">
    Go left while both are smaller, right while both are larger. The split is the answer.
  </FollowUp>
  <FollowUp q="Why isn't the diameter always the path through the root?">
    The longest path may bend deep inside one subtree.
  </FollowUp>
  <FollowUp q="Can you traverse a tree in order with O(1) extra space?">
    Yes, with Morris traversal: temporary links back up the tree.
  </FollowUp>
  <FollowUp q="When should you switch from DFS to BFS on a tree?">
    For levels or the nearest match: see [Tree BFS](/dsa/patterns/tree-bfs).
  </FollowUp>
</FollowUps>
