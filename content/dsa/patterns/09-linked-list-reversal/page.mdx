<TLDR>
Linked list problems are solved by **rewiring `next` pointers**, not by copying values. **Save `curr.next`** before you overwrite it, put a **dummy** in front when the head can change, and fix the two end links after a splice: O(n) time, O(1) space.
</TLDR>

## When to reach for it

<Callout kind="tip" title="Spot it in the problem statement">

- **Reverse** a list, part of a list, or every group of k nodes.
- **Merge**, **reorder** or **remove** nodes in place, where the head itself might go.
- Pair the front of a list with its **back read backwards**: reorder, palindrome check, twin sums.
- "O(1) extra memory", or "change only the links, not the values".

</Callout>

| Technique | Pointers | Use it when |
|---|---|---|
| Reverse in place | `prev`, `curr`, `next` | every arrow turns around |
| Dummy head | `dummy`, plus `tail` or `prev` | the head may change |
| Reverse a sublist and splice | `before`, `first`, plus the trio | only part of the list flips |
| Split, reverse, weave | `slow`/`fast`, the trio, `a`/`b` | the back half is needed backwards |
| Fixed gap | `fast` n + 1 ahead of `slow` | you count from the end |

## The core idea: save the link before you cut it

A node that nothing points at is gone for good. So every rewiring step runs in one order: **save** the link you still need, **overwrite** the pointer, then **advance**.

Reversal is the purest case. `prev` heads the reversed part, `curr` is the node being flipped, and `next` keeps the rest reachable while `curr.next` turns around:

<AlgoViz trace={reverseList} />

`prev` starts as `null` because the old head becomes the tail; when `curr` runs off the end, `prev` is the new head. Swap the save and flip lines and the rest of the list is lost. Try your own list with Edit input.

## Template 2: a dummy head

## Template 4: split, reverse, weave

Pairing the first node with the last needs the back half backwards, and a singly linked list can't walk backwards. So build it:

1. Find the middle with [fast and slow pointers](/dsa/patterns/fast-slow-pointers).
2. Cut there (`slow.next = null`) and reverse the back half.
3. Walk both halves together: compare them (palindrome) or weave them (reorder).

The weave rewrites two links per step, so save both successors first, then link `a → b → aNext`:

## Complexity

| Technique | Time | Extra space |
|---|---|---|
| Reverse in place | O(n) | O(1) (recursive: O(n) call stack) |
| Dummy head: merge, remove | O(n + m) / O(n) | O(1): one dummy node |
| Reverse a sublist, or every group of k | O(n): each node reversed at most once | O(1) |
| Split, reverse, weave | O(n): three linear passes | O(1) |
| Copy values into an array instead | O(n) | O(n) |

## JavaScript you'll use

<JsRef to={["linked-list-tree-nodes", "destructuring-spread"]} />

```js
const dummy = new ListNode(0, head);           // a node in front of the head
const next = curr.next;                         // save before overwriting
curr.next = prev;                               // flip
[curr.next, prev, curr] = [prev, curr, curr.next]; // all three steps at once
return dummy.next;                              // the real head, even if it changed
```

The one-line swap works because the right side is evaluated first. Left-side order still matters: `[prev, curr, curr.next] = [curr, curr.next, prev]` moves `curr` before writing `curr.next`, so it hits the wrong node.

<Callout kind="warning">

- Returning `head` after it moved: return `prev` after a reversal and `dummy.next` after any dummy edit.
- Reversing the back half without cutting first: the result has a cycle.
- Reading `node.next.next` without checking `node.next`: a TypeError on lists of length 0, 1 or 2.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="Iterative or recursive reversal: which would you write?">
    Iterative: same O(n) time, O(1) space. Recursion (`reverse(head.next)`, then `head.next.next = head; head.next = null`) holds one frame per node and can overflow on lists of tens of thousands of nodes.
  </FollowUp>
  <FollowUp q="Why use a dummy node instead of special-casing the head?">
    It gives the head a predecessor, so head edits become the general case: fewer branches, fewer bugs, for one extra object.
  </FollowUp>
  <FollowUp q="How do you rotate a list to the right by k places?">
    Find the length `n` and the tail, set `k %= n`, and join the tail to the head. Walk `n - k - 1` steps to the new tail, take its next as the new head, and cut: O(n) time, O(1) space.
  </FollowUp>
  <FollowUp q="How do you add two numbers stored as lists with the most significant digit first?">
    Reverse both, add digit by digit with a carry behind a dummy, then reverse the result. If the inputs must stay intact, pop the digits from two stacks instead.
  </FollowUp>
  <FollowUp q="Reverse Nodes in k-Group: how do you leave the last short group alone?">
    Check before you reverse: walk k steps from `before` and stop at `null`. Or count once and reverse exactly `Math.floor(n / k)` groups.
  </FollowUp>
</FollowUps>
