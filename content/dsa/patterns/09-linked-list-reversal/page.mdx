<TLDR>
Linked list problems are solved by **rewiring `next` pointers**. **Save `curr.next`** before you overwrite it, and put a **dummy** node in front when the head can change. O(n) time, O(1) space.
</TLDR>

## When to reach for it

<Callout kind="tip" title="Spot it in the problem statement">

- **Reverse** a list, part of it, or every group of k nodes.
- **Merge**, **reorder** or **remove** nodes in place, where the head might go.
- Pair the front with the **back read backwards**: reorder, palindrome.
- "O(1) extra memory" or "change the links, not the values".

</Callout>

| Technique | Pointers | Use it when |
|---|---|---|
| Reverse in place | `prev`, `curr`, `next` | every arrow turns around |
| Dummy head | `dummy`, plus `tail` or `prev` | the head may change |
| Reverse a sublist and splice | `before`, `first`, plus the trio | only part of the list flips |
| Split, reverse, weave | `slow`/`fast`, the trio, `a`/`b` | the back half is needed backwards |
| Fixed gap | `fast` n + 1 ahead of `slow` | you count from the end |

## The core idea: save the link before you cut it

Picture a train where each car is coupled only to the car behind it. Uncouple a car before you note who was behind it, and the rest of the train is lost. So: **save** the link, **overwrite** it, **advance**. Three pointers do it: `prev` (the flipped part), `curr` (the car being flipped) and `next` (the saved rest):

<AlgoViz trace={reverseList} />

`prev` starts as `null`: the old head becomes the tail. At the end, `prev` is the new head.

## Complexity

| Technique | Time | Extra space |
|---|---|---|
| Reverse in place | O(n) | O(1) (recursive: O(n) call stack) |
| Dummy head: merge, remove | O(n + m) / O(n) | O(1): one dummy node |
| Reverse a sublist, or every group of k | O(n): each node reversed at most once | O(1) |
| Split, reverse, weave | O(n): three linear passes | O(1) |
| Copy values into an array instead | O(n) | O(n) |

## JavaScript you'll use

<JsRef to={["linked-list-tree-nodes", "destructuring-spread"]} />

```js
const dummy = new ListNode(0, head);           // a node in front of the head
const next = curr.next;                         // save before overwriting
curr.next = prev;                               // flip
[curr.next, prev, curr] = [prev, curr, curr.next]; // all three steps at once
return dummy.next;                              // the real head, even if it changed
```

The right side is evaluated first, but order on the left still matters.

<Callout kind="warning">

- Returning `head` after it moved: return `prev` or `dummy.next`.
- Reversing the back half without cutting first: you get a cycle.
- Reading `node.next.next` without checking `node.next`.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="Iterative or recursive reversal?">
    Iterative: O(1) space. Recursion can overflow on long lists.
  </FollowUp>
  <FollowUp q="Why use a dummy node?">
    The head gets a predecessor, so editing it needs no special case.
  </FollowUp>
  <FollowUp q="How do you rotate a list right by k?">
    Join the tail to the head, walk `n - k % n - 1` steps to the new tail, and cut.
  </FollowUp>
  <FollowUp q="Add two numbers stored as lists, most significant digit first?">
    Reverse both, add with a carry, reverse the result. Or use two stacks.
  </FollowUp>
  <FollowUp q="Reverse in k-groups: how do you leave a short last group alone?">
    Walk k steps from `before` first. Stop if you hit `null`.
  </FollowUp>
</FollowUps>
