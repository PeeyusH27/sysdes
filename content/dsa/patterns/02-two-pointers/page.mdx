<TLDR>
Two fingers on a row replace a nested loop with one pass, because **every step rules out an element for good**.
</TLDR>

## When to reach for it

<Callout kind="tip" title="Spot it in the problem statement">

- The input is **sorted**, or you may sort it.
- You need a **pair or triplet** that meets a sum or difference condition.
- You must work **in place**, or compare something with its **mirror image**.

</Callout>

| Variant | Which pointer moves | Classic problems |
|---|---|---|
| Opposite ends | the end that can't be in the answer | pair sum, palindrome |
| Read/write | `read` always, `write` when a value is kept | remove duplicates |
| One per input | the one just used | merge sorted arrays |

## The core idea: every step discards something

Picture a sorted row of numbers with one finger on each end. Add the two numbers you touch.

- Too **small**? The left number is too small even with the biggest partner left, so it fits no pair. Move the left finger in.
- Too **big**? Same for the right number. Move the right finger in.

Each move throws one number away, so you finish in `n - 1` steps, not `n(n - 1) / 2` pair checks. Watch the discarded values fade:

Can't say "this element can never be in an answer"? Then two pointers is the wrong tool.

## Step by step

<Steps>
  <Step title="Decide what each pointer means">
    Your invariant: "everything outside `left..right` is ruled out".
  </Step>
  <Step title="Pick the starting positions">
    Opposite ends: `0` and `n - 1`.
  </Step>
  <Step title="Choose which pointer moves, and prove it">
    Say which element each case rules out.
  </Step>
  <Step title="Handle a match">
    Record it, then move a pointer.
  </Step>
  <Step title="Stop when the pointers meet">
    Pairs need two indices: `while (left < right)`.
  </Step>
</Steps>

## Complexity

| Variant | Time | Extra space |
|---|---|---|
| Opposite ends, sorted input | O(n) | O(1) |
| Read/write compaction | O(n) | O(1) |
| 3Sum: fix one, then opposite ends | O(n²) | O(1) |
| Merge two sorted inputs | O(n + m) | O(n + m) |

## JavaScript you'll use

<JsRef to={["sorting", "destructuring-spread", "arrays"]} />

```js
nums.sort((a, b) => a - b);                  // numeric sort: nums.sort() compares strings!
[nums[i], nums[j]] = [nums[j], nums[i]];     // swap in place without a temp variable
const last = nums.at(-1);                    // last element, same as nums[nums.length - 1]
s[i].toLowerCase() === s[j].toLowerCase();   // case-insensitive character compare
```

<Callout kind="warning">

- `nums.sort()` without a comparator: `[10, 9, 1]` sorts to `[1, 10, 9]`.
- Recording a match without moving a pointer: the loop never ends.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="Two Sum on an unsorted array: two pointers or a hash map?">
    A hash map: one pass, and it keeps indices. Two pointers wins on sorted input or when O(1) space is required.
  </FollowUp>
  <FollowUp q="How do you extend 3Sum to 4Sum?">
    Fix numbers with nested loops until two remain, then walk the ends.
  </FollowUp>
  <FollowUp q="Why is moving the shorter wall safe in Container With Most Water?">
    Any container keeping the shorter wall is narrower and no taller, so that wall is ruled out.
  </FollowUp>
  <FollowUp q="When does two pointers not apply?">
    When no move safely discards anything, like an unsorted sum target. Use hashing instead.
  </FollowUp>
</FollowUps>
