<TLDR>
Two indices replace an O(n²) nested loop with one O(n) pass, because **every step rules out an element for good**. Use opposite ends on sorted or mirrored input, read/write pointers to compact in place, and one pointer per input to merge.
</TLDR>

## When to reach for it

<Callout kind="tip" title="Spot it in the problem statement">

- The input is **sorted**, or you may sort it.
- You need a **pair or triplet** that meets a sum or difference condition.
- You must work **in place**, or compare something with its **mirror image**.

</Callout>

| Variant | Which pointer moves | Classic problems |
|---|---|---|
| Opposite ends | the end that can't be in the answer | pair sum, palindrome, container with most water |
| Read/write | `read` every step, `write` only when a value is kept | remove duplicates, move zeroes |
| One per input | the one whose value was just used | merge sorted arrays, squares of a sorted array |

## The core idea: every step discards something

Brute force checks all `n(n - 1) / 2` pairs. On a **sorted** array, the sum of the two ends tells you which end is useless:

- Too **small**? `nums[left]` plus the **largest** remaining value is still too small, so `nums[left]` is in no pair: `left++`.
- Too **big**? `nums[right]` plus the **smallest** remaining value is still too big: `right--`.

Each comparison drops one index, so the scan ends within `n - 1` steps. Watch the discarded values fade:

<AlgoViz trace={pairSum} />

That argument, "this element can never be in an answer", makes every two-pointer solution correct. Can't state it for your problem? Then two pointers is the wrong tool.

## Step by step

<Steps>
  <Step title="Decide what each pointer means">
    One sentence, your invariant: "everything outside `left..right` is ruled out" or "everything before `write` is final".
  </Step>
  <Step title="Pick the starting positions">
    Opposite ends: `0` and `n - 1`. Read/write: both at the start. One per input: index 0 of each.
  </Step>
  <Step title="Choose which pointer moves, and prove it">
    Say which element each case rules out, and move exactly that pointer. Never "just in case".
  </Step>
  <Step title="Handle a match">
    Record it, then move a pointer so the loop progresses. Skip equal values here if duplicates matter.
  </Step>
  <Step title="Stop when the pointers meet">
    Pairs need two indices: `while (left < right)`. Use `<=` only when each index is handled alone, as in Trapping Rain Water.
  </Step>
</Steps>

## Complexity

| Variant | Time | Extra space |
|---|---|---|
| Opposite ends on sorted input | O(n) | O(1) |
| Opposite ends after sorting | O(n log n) for the sort | O(1) to O(n), engine-dependent |
| Read/write compaction | O(n) | O(1) |
| 3Sum: fix one, then opposite ends | O(n²) | O(1) besides the output |
| Merge two sorted inputs | O(n + m) | O(n + m) output |

## JavaScript you'll use

<JsRef to={["sorting", "destructuring-spread", "arrays"]} />

```js
nums.sort((a, b) => a - b);                  // numeric sort: nums.sort() compares strings!
[nums[i], nums[j]] = [nums[j], nums[i]];     // swap in place without a temp variable
const last = nums.at(-1);                    // last element, same as nums[nums.length - 1]
s[i].toLowerCase() === s[j].toLowerCase();   // case-insensitive character compare
```

"In place" means changing the array you were given; `nums = nums.filter(…)` only rebinds your local variable.

<Callout kind="warning">

- `nums.sort()` without a comparator: `[10, 9, 1]` sorts to `[1, 10, 9]`.
- Recording a match without moving a pointer: the loop never ends.
- Skipping duplicates by comparing with the **next** element before using the current one, which loses answers like `[-1, -1, 2]`.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="Two Sum on an unsorted array: two pointers or a hash map?">
    A hash map: one O(n) pass that keeps the original indices. Two pointers wins on sorted input or when O(1) space is required.
  </FollowUp>
  <FollowUp q="How do you extend 3Sum to 4Sum, or to k numbers?">
    Sort, fix numbers with nested loops until two remain, then walk the ends: O(n^(k-1)), skipping duplicates at every level. Sums stay exact up to 2^53.
  </FollowUp>
  <FollowUp q="How do you know moving the shorter wall is safe in Container With Most Water?">
    Every container that keeps the shorter wall is narrower and no taller, so none beats the current area: the shorter wall is ruled out, as in pair sum.
  </FollowUp>
  <FollowUp q="When does the two-pointer technique not apply?">
    When no move safely discards anything: an unsorted sum target, or a question that needs every pair. Use hashing, a different window, or nested loops.
  </FollowUp>
</FollowUps>
