<TLDR>
A hash map or set **remembers what you've already seen**, so "is it there?", "how many?" and "where?" cost O(1) on average. One O(n) pass replaces an O(n²) nested loop, paid for with O(n) memory.
</TLDR>

## When to reach for it

<Callout kind="tip" title="Spot it in the problem statement">

- You keep asking **"have I seen this before?"** or **"how many times?"**
- Each element needs a **partner**: `target - x`, or an earlier running total.
- The brute force's inner loop only **searches**, or items must be **grouped**.

</Callout>

| Variant | Remembers | Classic problems |
|---|---|---|
| Seen set (`Set`) | which values appeared | contains duplicate, longest consecutive sequence |
| Frequency map | value → count | valid anagram, first unique character, top k frequent |
| Complement map | value → index or count | two sum, subarray sum equals k |
| Group by key | canonical key → members | group anagrams |

## The core idea: replace the inner search with a lookup

Most brute forces here scan the other elements for a duplicate, a partner, a match: an O(n) search paid n times. A hash structure deletes that scan. Store what each element tells you as you pass, and later elements **ask the map** instead.

The invariant: **the map holds exactly the elements before the current index.** So **look up, then insert**: the current element can't match itself, and every pair is found once, at its second element.

The price: O(n) memory, and a string key costs time proportional to its length to hash. "O(1)" means *on average*.

## Step by step

<Steps>
  <Step title="Write the brute force and find the inner search">
    What does it look for? "An earlier `target - x`", "a word with the same letters": that is the map's question.
  </Step>
  <Step title="Choose what to remember">
    Presence: a `Set`. How many: value → count. Where: value → index. Which group: key → list.
  </Step>
  <Step title="Choose the key">
    Usually the value. Sometimes a **canonical form** that makes equivalent items collide: sorted letters, `` `${r},${c}` ``.
  </Step>
  <Step title="Decide the order of operations">
    Pairing with earlier elements: look up **before** inserting. Comparing two whole inputs (anagrams): count first, then check.
  </Step>
  <Step title="Read off the answer">
    Return on the first hit, or make a final pass, over the input (not the map) when **order** matters.
  </Step>
</Steps>

## Complexity

| Template | Time | Extra space |
|---|---|---|
| Seen set, frequency map | O(n) | O(n), or O(k) for k symbols |
| Complement lookup | O(n) | O(n) |
| Group by sorted key | O(n · k log k), strings of length k | O(n · k) |
| Group by count signature | O(n · k) | O(n · k) |

The brute forces they replace: O(n²) pair checks, or O(n² · k) word-by-word comparisons.

## JavaScript you'll use

<JsRef to={["map-set", "objects", "strings"]} />

```js
count.set(x, (count.get(x) ?? 0) + 1);           // increment, starting from 0
if (seen.has(need)) return [seen.get(need), i];  // has(), not get(): an index can be 0
const counts = new Array(26).fill(0);
counts[ch.charCodeAt(0) - 97]++;                 // letter counter without a Map
const key = [...word].sort().join('');           // canonical key for anagrams
return [...groups.values()];                     // Map values → array of groups
```

The trap: arrays and objects are keys **by reference**, so `seen.add([1, 2])` then `seen.has([1, 2])` is `false`. Encode composite keys as strings or numbers.

<Callout kind="warning">

- Inserting before looking up, so an element pairs with itself: `[3, 4]` with target 6 returns `[0, 0]`.
- `if (map.get(k))` when the stored index or count can be `0`. Use `has`.
- Counting with a plain object: `counts["constructor"]` already exists on `{}`, so the word "constructor" breaks `(counts[w] || 0) + 1`. Use a `Map`.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="Hash map or sorting: which would you pick?">
    Hashing: O(n) expected time, O(n) memory. Sorting: O(n log n), little memory and a predictable worst case, so pick it when memory is tight or the data arrives sorted.
  </FollowUp>
  <FollowUp q="What is the worst case of a hash map lookup, and does it matter?">
    O(n) when many keys collide, and attackers can force that, which is why engines randomise string hashing. Say "O(1) on average" unless asked about adversarial input.
  </FollowUp>
  <FollowUp q="How do you group anagrams when the words are very long?">
    Swap the O(k log k) sorted key for an O(k) count signature: 26 counts joined with a separator (`1#0#2#…`). Without the separator, counts 1, 11 and 11, 1 both give "111".
  </FollowUp>
  <FollowUp q="The data doesn't fit in memory. Can you still count distinct items or find duplicates?">
    Exactly: hash-partition into files that fit in memory, then map each file. Approximately: a Bloom filter (seen before?), HyperLogLog (distinct count in a few kilobytes) or a count-min sketch (frequencies).
  </FollowUp>
</FollowUps>
