<TLDR>
A hash map is a **notebook of what you have seen**. One look costs one step, so a nested loop becomes one pass: O(n) time, O(n) memory.
</TLDR>

## The core idea: replace the inner search with a lookup

<Doodle name="index" size={150} caption />

Think of a book with edge tabs. Hunting for a chapter page by page is slow. Flipping to its tab is instant. A hash map is the tab.

A brute force scans the other elements for a match, again and again. Instead, write down what each element tells you as you pass. Later elements ask the notebook, not the list.

One rule: **look up first, then write down.** An element can't pair with itself, and every pair is found at its second element. Watch a set catch the first repeat:

<AlgoViz trace={seenSet} />

The price is O(n) memory. "O(1)" means on average.

## Step by step

<Steps>
  <Step title="Find the inner search in the brute force">
    "An earlier `target - x`" is the map's question.
  </Step>
  <Step title="Choose what to remember">
    Presence: `Set`. Count or index: value → count or index. Group: key → list.
  </Step>
  <Step title="Choose the key">
    Usually the value, or a **canonical form** like sorted letters.
  </Step>
  <Step title="Pick the order">
    Pairing with earlier elements: look up **before** inserting.
  </Step>
  <Step title="Read off the answer">
    Return on the first hit, or rescan when **order** matters.
  </Step>
</Steps>

## Complexity

| Template | Time | Extra space |
|---|---|---|
| Seen set, frequency map | O(n) | O(n) |
| Complement lookup | O(n) | O(n) |
| Group by sorted key | O(n · k log k) | O(n · k) |
| Group by count signature | O(n · k) | O(n · k) |

## JavaScript you'll use

<JsRef to={["map-set", "objects", "strings"]} />

```js
count.set(x, (count.get(x) ?? 0) + 1);           // increment, starting from 0
if (seen.has(need)) return [seen.get(need), i];  // has(), not get(): an index can be 0
const counts = new Array(26).fill(0);
counts[ch.charCodeAt(0) - 97]++;                 // letter counter without a Map
const key = [...word].sort().join('');           // canonical key for anagrams
return [...groups.values()];                     // Map values → array of groups
```

Arrays are keys **by reference**: `seen.has([1, 2])` is `false` after adding `[1, 2]`. Use strings.

<Callout kind="warning">

- Inserting first: `[3, 4]` with target 6 returns `[0, 0]`.
- `if (map.get(k))` when the stored value can be `0`. Use `has`.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="Hash map or sorting: which would you pick?">
    Hashing: O(n) time, O(n) memory. Sorting: O(n log n), little memory. Pick sorting when memory is tight.
  </FollowUp>
  <FollowUp q="What is the worst case of a hash map lookup?">
    O(n) when many keys collide. Say "O(1) on average" unless asked about attackers.
  </FollowUp>
  <FollowUp q="How do you group anagrams when the words are very long?">
    Use 26 counts joined with a separator (`1#0#2#…`) as the key: O(k). Without the separator, 1,11 and 11,1 look the same.
  </FollowUp>
  <FollowUp q="The data doesn't fit in memory. Now what?">
    Split it by hash into files that fit, then map each file. For estimates, use a Bloom filter or HyperLogLog.
  </FollowUp>
</FollowUps>
