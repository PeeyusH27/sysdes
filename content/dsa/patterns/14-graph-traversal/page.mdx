A grid is a graph in disguise: every cell is a node joined to its neighbours. **DFS** dives deep (flood a region). **BFS** spreads in rings, so it finds the **fewest steps**. Both are O(V + E).
</TLDR>

## The core idea: visit every node once

<Doodle name="queue" size={150} caption />

Exploring a maze, you keep a to-do list of places seen but not yet visited. Take one, add its unseen neighbours. The kind of list decides how you explore:

- A **stack** (newest first) dives down one corridor: **depth-first**.
- A **queue** (oldest first) spreads like ripples in a pond, finishing every node at distance d before d + 1: **breadth-first**.

Grids are full of loops, so you need a **visited mark**. Mark a node **when you push it**, so nothing is queued twice. To count pieces, scan every node: each unmarked one starts a new piece.

## Building the graph

Graphs arrive as an **edge list** (`[[0, 1], [1, 2]]`), an **adjacency list** (`graph[i]` lists the neighbours of `i`), or an **implicit** graph (a grid). Convert an edge list once, so finding neighbours is fast:

For a grid, build nothing. Use a **directions array**, `[[1, 0], [-1, 0], [0, 1], [0, -1]]`, behind a bounds check.

## Template 1: DFS for regions

Use DFS when the question is **what** can be reached, not **how far**. The recursive version reads like the definition ("this cell, plus everything reachable from its neighbours") and can return values up, as <ProblemLink slug="max-area-of-island" /> does to add up a size. The iterative version can't overflow the call stack on a huge region.

## Template 2: BFS for the fewest steps

A node is **first** found along a shortest path. Set `dist[next] = dist[node] + 1` then, and every distance comes out in one pass.

<AlgoViz trace={bfsLevels} />

Use a **head index**, not `queue.shift()`, which can make BFS O(V²).

For "how many steps", process one **level** at a time, as <ProblemLink slug="word-ladder" /> does.

## Template 3: multi-source BFS

How far is each cell from the **nearest** source (rotten orange, exit)? Don't run one BFS per source. Queue **all** sources at distance 0 and run once, as if one imaginary source touched them all.

## Complexity

| Traversal | Time | Extra space |
|---|---|---|
| DFS or BFS on an adjacency list | O(V + E) | O(V) |
| DFS or BFS on an m × n grid | O(m·n): four neighbour checks per cell | O(m·n) |
| Counting components (scan + flood) | O(V + E) | O(V) |
| Multi-source BFS, any number of sources | O(V + E) | O(V) |
| Building an adjacency list | O(V + E) | O(V + E) |

## JavaScript you'll use

<JsRef to={["graphs-in-js", "stack-queue-deque", "map-set"]} />

```js
const adj = Array.from({ length: n }, () => []);                        // n separate arrays
const seen = Array.from({ length: rows }, () => new Array(cols).fill(false));
const dirs = [[1, 0], [-1, 0], [0, 1], [0, -1]];
for (const [dr, dc] of dirs) { const nr = r + dr, nc = c + dc; /* … */ }
if (grid[nr]?.[nc] !== "1") continue;      // out-of-bounds reads give undefined instead of throwing
for (let head = 0; head < queue.length; head++) { const node = queue[head]; /* … */ }
const key = `${r},${c}`;                   // a cell as a Set or Map key (or r * cols + c)
```

`new Array(rows).fill(new Array(cols).fill(false))` puts the **same** row in every slot. And `seen.has([r, c])` is always `false`: use a string or number key.

<Callout kind="warning">

- Forgetting to mark the **start** node or the sources.
- Checking bounds after indexing: `grid[-1][0]` throws.
- Comparing `"1"` with `1`.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="DFS or BFS: when does the choice matter?">
    For **fewest steps** with equal costs, only BFS is correct (with weights, see [Shortest Paths](/dsa/patterns/shortest-paths)). For reachability, both work.
  </FollowUp>
  <FollowUp q="Why mark a node visited when it is enqueued, not dequeued?">
    Otherwise a node can be queued once per neighbour, and the queue grows to O(E). Marking on enqueue gives one entry per node.
  </FollowUp>
  <FollowUp q="You can't modify the input grid. What changes?">
    Keep a separate mark: a boolean grid or a `Uint8Array(rows * cols)`.
  </FollowUp>
  <FollowUp q="How would you return the shortest path itself?">
    Store `parent[next] = node`, then follow parents back from the target and reverse.
  </FollowUp>
  <FollowUp q="The graph is implicit and enormous. How can you make BFS faster?">
    Bidirectional BFS: search from both ends until they meet, about 2·b^(d/2) nodes instead of b^d.
  </FollowUp>
</FollowUps>
