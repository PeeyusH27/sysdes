<TLDR>
A **binary heap** keeps the best item at its root: **peek** in O(1), **push** and **pop** in O(log n). Most heap problems are **top k** (O(n log k)), **k-way merge** or **two heaps** for a running median.
</TLDR>

## When to reach for it

<Callout kind="tip" title="Spot it in the problem statement">

- "The **k** largest, smallest, most frequent or closest", or "the **kth** largest".
- **Merge k sorted** lists, arrays or streams.
- A **running** answer over a stream: the median so far.

</Callout>

| Variant | The heap holds | Classic problems |
|---|---|---|
| Top k | the best k so far | kth largest, top k frequent, k closest points |
| K-way merge | one head per sorted input | merge k sorted lists, kth smallest in a sorted matrix |
| Two heaps | the lower and upper halves | running median, sliding window median |
| Best first | every pending item, **cheapest** first | task scheduling, meeting rooms, Dijkstra |

## The core idea: a tree that is only half sorted

Think of a tournament bracket. The champion sits at the top, and every winner beat the players below. Players on the same level are in no order, and that laziness keeps updates cheap. A **heap** is that bracket: every parent beats its children.

It has no gaps, so it fits in a plain array: the children of index `i` are `2i + 1` and `2i + 2`. A million items is only 20 levels deep.

- **push**: add at the end, then **sift up** while better than the parent.
- **pop**: take the root, move the last item up, then **sift down** with the **better child**.

That is at most one swap per level:

## Step by step

<Steps>
  <Step title="Ask what you need the best of, repeatedly">
    The min or max **many times**: heap. Just once: scan.
  </Step>
  <Step title="Decide what goes into the heap">
    Numbers, pairs, list nodes.
  </Step>
  <Step title="Write the comparator and check its direction">
    The k largest need a **min**-heap.
  </Step>
  <Step title="Bound the size">
    Pop at k + 1 for top k.
  </Step>
  <Step title="Read the answer">
    `peek()` for the kth best, or pop all.
  </Step>
</Steps>

## Template 1: a binary heap with a comparator

One class, one comparator: a min-heap, a max-heap, or pairs ordered by any key.

<CodeTabs files={['snippets/heap.js']} java={['snippets/java/Heap.java']} python={['snippets/python/heap.py']} />

```js
new Heap((a, b) => a - b);          // min-heap of numbers
new Heap((a, b) => b - a);          // max-heap of numbers
new Heap((a, b) => a[1] - b[1]);    // pairs, smallest second element first
new Heap((a, b) => a.val - b.val);  // linked list nodes by value
```

Interviews expect you to write your own `siftUp` and `siftDown`.

## Template 2: top k with a heap of size k

To keep the k **largest**, keep a **min**-heap of at most k. Its root is the weakest of the top k. Push each value; when the heap reaches k + 1, pop the root. At the end the root is the kth largest.

## Template 4: two heaps for a running median

Keep the **lower half** in a max-heap and the **upper half** in a min-heap. Keep every low value at most every high value, and the halves equal in size (the lower may have one more).

The median is the lower top, or the average of both tops. To add a number, push it low, move the lower top up, and rebalance.

## Complexity

| Operation or variant | Time | Extra space |
|---|---|---|
| `peek` | O(1) | O(1) |
| `push`, `pop` on n items | O(log n): one swap per level | O(1) |
| Build a heap from n items | O(n log n) by pushing, O(n) bottom-up | O(n) |
| Top k of n items | O(n log k) | O(k) |
| K-way merge of N items from k inputs | O(N log k) | O(k) |
| Running median | O(log n) per number, O(1) per median | O(n) |

## JavaScript you'll use

<JsRef to={["heap", "classes", "sorting"]} />

```js
const parent = (i - 1) >> 1;                 // index of the parent: halve and round down
const left = 2 * i + 1, right = 2 * i + 2;   // indices of the children
[a[i], a[j]] = [a[j], a[i]];                 // swap two slots
const byCount = (a, b) => a[1] - b[1];       // comparators return numbers, never booleans
for (const entry of counts) heap.push(entry); // Map entries are [key, value] pairs
```

`arr.sort()` after every insert is O(n log n): don't fake a heap.

<Callout kind="warning">

- A comparator that returns a **boolean**. Return a negative, zero or positive number.
- siftDown that swaps with the first child, not the **better of the two**.
- pop on a one-item heap leaving a **ghost value**.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="Kth largest element: heap, sort or quickselect?">
    Sorting is O(n log n). A size-k heap is O(n log k) and works on a **stream**. Quickselect is O(n) on average.
  </FollowUp>
  <FollowUp q="Why can a heap be built in O(n)?">
    Sift down every non-leaf, last to first. Half the nodes are leaves.
  </FollowUp>
  <FollowUp q="How would you change an item's priority?">
    Keep a Map from item to index. Or push the new version and skip stale ones.
  </FollowUp>
  <FollowUp q="Running median when every number is between 0 and 100?">
    A count array of 101 buckets.
  </FollowUp>
  <FollowUp q="When is a heap the wrong tool?">
    Sorting once, arbitrary lookups or ranges, or k close to n.
  </FollowUp>
</FollowUps>
