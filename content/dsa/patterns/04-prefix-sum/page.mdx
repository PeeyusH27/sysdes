<TLDR>
A prefix sum array stores **running totals**, so any range sum is one subtraction: O(n) to build, O(1) per query. A hash map of prefixes finds subarrays with a given sum in one pass, and a **difference array** makes range updates O(1).
</TLDR>

## When to reach for it

<Callout kind="tip" title="Spot it in the problem statement">

- You need the **sum of a range** many times, on data that doesn't change.
- "**Subarray sums to k**", "divisible by k", "equal 0s and 1s", often with negative numbers.
- Each element needs "everything to its left" and "to its right", or many **range updates** come before one read.

</Callout>

| Variant | What you store | Classic problems |
|---|---|---|
| 1D prefix sums | `prefix[i]` = sum of the first i values | range sum query, pivot index |
| Prefix sum + hash map | running sum → count, or → first index | subarray sum equals k, contiguous array |
| Prefix and suffix scans | running product or max from each side | product of array except self, trapping rain water |
| 2D prefix sums | `P[r][c]` = sum of the top-left rectangle | range sum query 2D |
| Difference array | where values change | car pooling, flight bookings |

## The core idea: a range is the difference of two prefixes

Let `prefix[i]` be the sum of the first `i` values, with `prefix[0] = 0`. The range `left..right` is "everything up to `right`" minus "everything before `left`":

`sum(nums[left..right]) = prefix[right + 1] - prefix[left]`

One pass builds `prefix`; after that, every range costs one subtraction, whatever its length. The leading 0 lets ranges start at index 0 with no special case.

<AlgoViz trace={prefixBuildQuery} />

It works for **any** values, negatives included, because subtraction undoes addition exactly. It fails for max or min: you can't "subtract" a max, so those need a sparse table or a segment tree.

## Step by step

<Steps>
  <Step title="Write the quantity as a range sum">
    Sometimes after a relabel: equal 0s and 1s is "sum 0" once each 0 counts as -1; "divisible by k" compares prefixes modulo k.
  </Step>
  <Step title="Choose the prefix convention">
    n + 1 entries with `prefix[0] = 0`, or one running variable if you only need the current prefix.
  </Step>
  <Step title="Turn the condition into a lookup">
    `P(j) - P(i) = k` becomes `P(i) = P(j) - k`: "did an earlier prefix have this value?", a hash map lookup.
  </Step>
  <Step title="Decide what the map stores">
    Counting: how often each prefix sum occurred, seeded 0 → 1. Longest: the **first** index of each, seeded 0 → -1.
  </Step>
  <Step title="Look up, then record">
    Query `sum - k` before inserting `sum`, so a prefix never pairs with itself.
  </Step>
</Steps>

## Template 2: prefix sum + hash map

A subarray ending at `j` sums to `k` exactly when an **earlier** prefix equals `sum - k`: the complement lookup from [Hash Maps and Sets](/dsa/patterns/hashing), on running sums. Keeping each prefix's **first** index makes the match as long as possible.

To **count** instead, store how often each prefix sum occurred (seeded 0 → 1) and add the count for `sum - k` at every step: that is <ProblemLink slug="subarray-sum-equals-k" />. <ProblemLink slug="contiguous-array" /> is the longest version with `k = 0`, once every 0 counts as -1.

## Template 3: 2D prefix sums

`P[r][c]` sums the rectangle from the top-left corner to row `r - 1`, column `c - 1` (with a padding row and column of zeros). Any rectangle is four lookups by **inclusion-exclusion**: the big one, minus the strips above and to the left, plus the corner cut twice.

<CodeTabs files={['snippets/prefix-2d.js']} java={['snippets/java/Prefix2d.java']} python={['snippets/python/prefix_2d.py']} />

| Step | Formula |
|---|---|
| Build | `P[r + 1][c + 1] = grid[r][c] + P[r][c + 1] + P[r + 1][c] - P[r][c]` |
| Query rows r1..r2, columns c1..c2 | `P[r2 + 1][c2 + 1] - P[r1][c2 + 1] - P[r2 + 1][c1] + P[r1][c1]` |

Building is O(rows × cols); each rectangle query is O(1).

## Template 4: difference arrays for range updates

A **difference array** runs the idea backwards: it stores how much each value differs from the one before. Adding `delta` to a range changes two entries, `+delta` at its start and `-delta` just after its end; one final running sum rebuilds the values.

## Complexity

| Variant | Time | Extra space |
|---|---|---|
| Build 1D prefix sums | O(n) once, then O(1) per query | O(n), or O(1) with a running sum |
| Prefix sum + hash map | O(n), one pass | O(n) distinct prefix sums |
| 2D prefix sums | O(rows × cols), then O(1) per rectangle | O(rows × cols) |
| Difference array | O(1) per update, O(n) final pass | O(n) |

## JavaScript you'll use

<JsRef to={["arrays", "map-set"]} />

```js
const prefix = new Array(n + 1).fill(0);          // one extra slot for the empty prefix
for (let i = 0; i < n; i++) prefix[i + 1] = prefix[i] + nums[i];
const seen = new Map([[0, 1]]);                   // seed: the empty prefix, before index 0
count += seen.get(sum - k) ?? 0;                  // ?? 0 for "never seen"
const P = Array.from({ length: rows + 1 }, () => new Array(cols + 1).fill(0)); // 2D, rows not shared
```

The trap: reading past either end returns `undefined`, and `5 - undefined` is a silent `NaN`. Also, `new Array(rows).fill(new Array(cols))` makes every row the **same** array.

<Callout kind="warning">

- Mixing conventions: with n + 1 entries it's `prefix[r + 1] - prefix[l]`, never `prefix[r] - prefix[l - 1]`.
- Overwriting the first index of a prefix sum when you want the **longest** subarray.
- Putting a difference array's minus at `right + 1` when the range end is exclusive, or at `right` when it's inclusive.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="The array changes between queries. Does a prefix sum still work?">
    An update shifts every later prefix: O(n). With frequent updates, use a **Fenwick tree** (about 15 lines) or a segment tree, O(log n) for both.
  </FollowUp>
  <FollowUp q="How do you count subarrays whose sum is divisible by k?">
    Count prefix remainders mod k (seeded 0 → 1): two prefixes with the same remainder bound a divisible sum. Normalise with `((sum % k) + k) % k`, since JavaScript's `%` keeps the sign.
  </FollowUp>
  <FollowUp q="Sliding window or prefix sums: how do you choose?">
    Non-negative values and a longest or shortest bound: a window, O(1) space. Negatives, an exact sum or a count: prefix sums plus a hash map, O(n) space. Both are O(n) time.
  </FollowUp>
  <FollowUp q="How would you apply a million range increments to a huge array, then answer point queries?">
    Known up front: a difference array, O(1) each plus one O(n) pass. Sparse positions up to 10^9: sorted events and a sweep. Interleaved with queries: a Fenwick tree over the differences, O(log n) each.
  </FollowUp>
</FollowUps>
