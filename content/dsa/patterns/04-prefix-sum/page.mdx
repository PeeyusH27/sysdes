## The core idea: a range is the difference of two prefixes

Picture a staircase where each step is the total so far. The sum of any stretch is the height between two steps: top minus bottom.

Let `prefix[i]` be the sum of the first `i` values, with `prefix[0] = 0`. Then:

`sum(nums[left..right]) = prefix[right + 1] - prefix[left]`

One pass builds `prefix`. After that every range costs one subtraction, whatever its length.

<AlgoViz trace={prefixBuildQuery} />

It works for **any** values, negatives included, because subtraction undoes addition. It fails for max or min: you can't subtract a max.

## Step by step

<Steps>
  <Step title="Write the quantity as a range sum">
    Equal 0s and 1s: sum 0, with each 0 as -1.
  </Step>
  <Step title="Choose the prefix convention">
    n + 1 entries with `prefix[0] = 0`.
  </Step>
  <Step title="Turn the condition into a lookup">
    `P(j) - P(i) = k` becomes `P(i) = P(j) - k`: did an earlier prefix have this value?
  </Step>
  <Step title="Decide what the map stores">
    Counting: how often each prefix occurred, seeded 0 → 1. Longest: the **first** index, seeded 0 → -1.
  </Step>
  <Step title="Look up, then record">
    Query `sum - k` before inserting `sum`.
  </Step>
</Steps>

## Template 2: prefix sum + hash map

A subarray ending at `j` sums to `k` exactly when an **earlier** prefix equals `sum - k`. That is the lookup from [Hash Maps and Sets](/dsa/patterns/hashing), on running totals. Keep each prefix's **first** index to get the longest match.

## Template 3: 2D prefix sums

`P[r][c]` sums the rectangle from the top-left corner to row `r - 1`, column `c - 1`. Any rectangle is four lookups: the big one, minus the strips above and left, plus the corner cut twice.

<CodeTabs files={['snippets/prefix-2d.js']} java={['snippets/java/Prefix2D.java']} python={['snippets/python/prefix_2d.py']} />

| Step | Formula |
|---|---|
| Build | `P[r + 1][c + 1] = grid[r][c] + P[r][c + 1] + P[r + 1][c] - P[r][c]` |
| Query rows r1..r2, columns c1..c2 | `P[r2 + 1][c2 + 1] - P[r1][c2 + 1] - P[r2 + 1][c1] + P[r1][c1]` |

## Template 4: difference arrays for range updates

A **difference array** runs the idea backwards. Adding `delta` to a range changes two entries: `+delta` at its start, `-delta` just after its end. One running sum rebuilds the values.

## Complexity

| Variant | Time | Extra space |
|---|---|---|
| 1D prefix sums | O(n) once, then O(1) per query | O(n) |
| Prefix sum + hash map | O(n) | O(n) |
| 2D prefix sums | O(rows × cols), then O(1) per query | O(rows × cols) |
| Difference array | O(1) per update, O(n) final pass | O(n) |

## JavaScript you'll use

<JsRef to={["arrays", "map-set"]} />

```js
const prefix = new Array(n + 1).fill(0);          // one extra slot for the empty prefix
for (let i = 0; i < n; i++) prefix[i + 1] = prefix[i] + nums[i];
const seen = new Map([[0, 1]]);                   // seed: the empty prefix, before index 0
count += seen.get(sum - k) ?? 0;                  // ?? 0 for "never seen"
const P = Array.from({ length: rows + 1 }, () => new Array(cols + 1).fill(0)); // 2D, rows not shared
```

Reading past either end gives `undefined`, and `5 - undefined` is a silent `NaN`.

<Callout kind="warning">

- Mixing conventions: with n + 1 entries it's `prefix[r + 1] - prefix[l]`.
- Overwriting a prefix's first index when you want the **longest** subarray.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="The array changes between queries. Does a prefix sum still work?">
    Each update shifts every later prefix: O(n). For frequent updates use a **Fenwick tree**: O(log n) for both.
  </FollowUp>
  <FollowUp q="How do you count subarrays whose sum is divisible by k?">
    Count prefix remainders mod k (seeded 0 → 1). Two prefixes with the same remainder bound a divisible sum.
  </FollowUp>
  <FollowUp q="Sliding window or prefix sums: how do you choose?">
    Non-negative values and a longest or shortest bound: a window. Negatives, an exact sum or a count: prefix sums plus a map.
  </FollowUp>
  <FollowUp q="A million range increments, then point queries. What do you do?">
    A difference array: O(1) per update, one O(n) pass at the end.
  </FollowUp>
</FollowUps>
