<TLDR>
A sliding window is a frame over a row that **slides along instead of starting over**. Each element enters once and leaves once, so O(n · k) becomes O(n).
</TLDR>

## The core idea: update, don't recompute

Picture a frame over a row of boxes. Slide it one step: one box comes in, one goes out. Update the running total with those two changes instead of re-adding everything.

<AlgoViz trace={fixedWindow} />

A window that grows and shrinks needs a rule that only gets harder (or only easier) as the window grows.

- **At most** rules (k distinct, no repeats): once a window breaks the rule, every longer one from the same `left` does too. So `left` moves on for good.
- **At least** rules (sum at least target): once valid, longer windows can't beat it. So `left` is done.

Neither pointer moves back: at most 2n moves, so O(n) despite the `while` inside the `for`.

## Step by step

<Steps>
  <Step title="Check that a window fits">
    Negative numbers fail: use [Prefix Sums](/dsa/patterns/prefix-sum).
  </Step>
  <Step title="Choose the window's state">
    The smallest summary that answers "valid?" in O(1): a sum, or a `Map` of counts.
  </Step>
  <Step title="Write add(right) and remove(left)">
    `remove` must undo `add`.
  </Step>
  <Step title="Decide when left moves">
    Longest: **while** invalid. Shortest: **while** valid.
  </Step>
  <Step title="Record at the right moment">
    Longest: **after** the shrink loop. Shortest: **inside** it.
  </Step>
</Steps>

## Template 4: monotonic deque for window max or min

A sum survives an element leaving; a **maximum** doesn't. Keep a deque of indices with **decreasing** values. Pop smaller or equal ones from the back before pushing, and drop the front once it slides out. The front is the maximum.

## Complexity

| Variant | Time | Extra space |
|---|---|---|
| Fixed window | O(n) | O(1) for a sum |
| Longest or shortest valid window | O(n) | O(a) for an alphabet of size a |
| Monotonic deque | O(n) | O(k) |
| Brute force | O(n · k) or O(n²) | O(1) |

## JavaScript you'll use

<JsRef to={["map-set", "strings", "stack-queue-deque"]} />

```js
const len = right - left + 1;                 // window length with inclusive ends
count.set(ch, (count.get(ch) ?? 0) + 1);      // a character enters
if (count.get(out) === 1) count.delete(out);  // one leaves: delete at zero,
else count.set(out, count.get(out) - 1);      // so count.size = number of distinct
const counts = new Array(26).fill(0);         // lowercase letters only: faster than a Map
counts[s.charCodeAt(i) - 97]++;
let head = 0;                                 // deque front: dq[head++] instead of dq.shift()
```

Always delete a key when its count hits zero, or `count.size` lies.

<Callout kind="warning">

- Off-by-one sizes: the length is `right - left + 1`.
- Shrinking with `if` instead of `while`.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="Why does the window break with negative numbers?">
    Adding an element can shrink the sum, so neither pointer has a safe move. Use prefix sums plus a hash map.
  </FollowUp>
  <FollowUp q="How do you count subarrays with exactly k distinct values?">
    exactly(k) = atMost(k) - atMost(k - 1). Two O(n) passes.
  </FollowUp>
  <FollowUp q="Sliding window maximum: why a deque instead of a heap?">
    A heap that pops stale tops is O(n log n). The deque is O(n).
  </FollowUp>
  <FollowUp q="How would you keep a moving average over a live stream?">
    Keep the last k values and a running sum: add the new one, subtract the one it overwrites.
  </FollowUp>
</FollowUps>
