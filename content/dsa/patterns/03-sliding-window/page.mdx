<TLDR>
A sliding window keeps one contiguous range `[left, right]` and a running summary of it, **updated as the edges move** instead of recomputed. Each element enters once and leaves once, so O(n · k) or O(n²) becomes O(n).
</TLDR>

## When to reach for it

<Callout kind="tip" title="Spot it in the problem statement">

- You want the longest, shortest or number of **contiguous** ranges that obey a rule.
- The rule has a bound ("**at most** k distinct", "sum **at least** target", "**no** repeats") or a **fixed size** k.
- The values are non-negative, so growing a range never shrinks its sum.

</Callout>

| Variant | How the edges move | Classic problems |
|---|---|---|
| Fixed size | together: one in, one out | maximum average subarray, permutation in string |
| Longest valid | grow `right`; **while invalid**, move `left` | longest substring without repeats |
| Shortest valid | grow `right`; **while valid**, record, move `left` | minimum size subarray sum, minimum window substring |
| Monotonic deque | a deque keeps max or min candidates | sliding window maximum |

## The core idea: update, don't recompute

Neighbouring windows overlap almost completely: one element enters, one leaves. Two cheap updates replace re-adding all k values.

<AlgoViz trace={fixedWindow} />

Variable windows also need a rule that is **monotonic** in the window's size:

- **At most** rules (k distinct, no repeats): shrinking keeps a window valid. Once it turns invalid, every longer window from the same `left` is invalid too, so `left` moves on **for good**.
- **At least** rules (sum at least target, contains all of t): growing keeps it valid. Once `[left, right]` is valid, longer windows from `left` can't beat it, so `left` is done.

Neither pointer moves back: at most 2n moves, so O(n) despite the `while` inside the `for`.

## Step by step

<Steps>
  <Step title="Check that a window fits">
    Contiguous answer, monotonic rule. Sums with negative numbers fail: use [Prefix Sums](/dsa/patterns/prefix-sum).
  </Step>
  <Step title="Choose the window's state">
    The smallest summary that answers "valid?" in O(1): a running sum, a `Map` of counts, a `Set`, or a `missing` counter.
  </Step>
  <Step title="Write add(right) and remove(left)">
    Mirror images: `remove` must undo `add`, deleting keys whose count reaches 0.
  </Step>
  <Step title="Decide when left moves">
    Fixed: once the window is wider than k. Longest: **while** invalid. Shortest: **while** valid.
  </Step>
  <Step title="Record at the right moment">
    Fixed: once full (`right >= k - 1`). Longest: **after** the shrink loop. Shortest: **inside** it, before each `left++`.
  </Step>
</Steps>

## Template 4: monotonic deque for window max or min

A sum survives an element leaving; a **maximum** doesn't, because you don't know the runner-up. Keep a deque of indices whose values **decrease** from front to back:

- Before pushing `i`, pop back indices with values not bigger than `nums[i]`: older **and** no bigger, they can never be the maximum again.
- Drop the front index once it slides out. The front is always the window's maximum.

<AlgoViz trace={windowMaxDeque} />

<CodeTabs files={['snippets/window-max.js']} />

Each index is pushed and popped at most once: O(n). Flip the comparison for a minimum. Over prefix sums, the same deque finds the shortest subarray with sum at least k, negatives included.

## Complexity

| Variant | Time | Extra space |
|---|---|---|
| Fixed window | O(n) | O(1) for a sum, O(k) for counts |
| Longest or shortest valid window | O(n) | O(a) for an alphabet of size a |
| Monotonic deque | O(n) | O(k) |
| Brute force, for comparison | O(n · k) fixed, O(n²) or worse variable | O(1) |

## JavaScript you'll use

<JsRef to={["map-set", "strings", "stack-queue-deque"]} />

```js
const len = right - left + 1;                 // window length with inclusive ends
count.set(ch, (count.get(ch) ?? 0) + 1);      // a character enters
if (count.get(out) === 1) count.delete(out);  // one leaves: delete at zero,
else count.set(out, count.get(out) - 1);      // so count.size = number of distinct
const counts = new Array(26).fill(0);         // lowercase letters only: faster than a Map
counts[s.charCodeAt(i) - 97]++;
let head = 0;                                 // deque front: dq[head++] instead of dq.shift()
```

The trap: `count.size` counts **keys**, including those whose count dropped to 0, so always delete at zero.

<Callout kind="warning">

- Off-by-one sizes: the length is `right - left + 1`, and the first full window of size k ends at index `k - 1`.
- Shrinking with `if` instead of `while`, which leaves the window invalid when several elements must go.
- Recomputing the summary every step (`slice`, `reduce`, a fresh `Set`), which quietly brings back O(n · k).

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="Why does the window break with negative numbers, and what replaces it?">
    With negatives, adding an element can shrink the sum, so neither pointer has a safe move. Use prefix sums plus a hash map to count sum-k subarrays, or a monotonic deque of prefix sums for the shortest with sum at least k: both O(n).
  </FollowUp>
  <FollowUp q="How do you count subarrays with exactly k distinct values?">
    exactly(k) = atMost(k) - atMost(k - 1), because "at most" is monotonic. Count at-most windows by adding `right - left + 1` at each `right`: two O(n) passes.
  </FollowUp>
  <FollowUp q="Sliding window maximum: why a deque instead of a heap?">
    A max-heap of `[value, index]` that pops stale tops is O(n log n) and easy to explain. The deque is O(n): mention the heap, then give the deque.
  </FollowUp>
  <FollowUp q="How would you keep a moving average over a live stream?">
    A ring buffer of the last k values plus a running sum: add the new value, subtract the one it overwrites, O(1) per update. Floats drift, so recompute the sum from the buffer now and then.
  </FollowUp>
</FollowUps>
