<TLDR>
A grid problem is usually **index arithmetic in disguise**: rotate with two swaps, walk a spiral with four moving walls, mark rows inside the grid itself. Get the coordinates right and most of these are O(rows × columns) time with O(1) extra space.
</TLDR>

## When to reach for it

<Callout kind="tip" title="Spot it in the problem statement">

- You **rotate, flip or transpose** a grid, or read it in a **spiral** or along **diagonals**.
- The statement says **"in place"** or "with O(1) extra space" on a 2D array.
- Every cell updates **at the same time** (a generation, a flood).
- Rows and columns are **sorted**, and you must search it fast.

</Callout>

| Variant | Key move | Classic problems |
|---|---|---|
| Rotate / transpose | swap `(i, j)` with `(j, i)`, reverse rows | rotate image |
| Layers and boundaries | four walls that move inward | spiral matrix |
| Marker row and column | store flags in the grid itself | set matrix zeroes |
| Simulation | encode old and new state in one cell | game of life |
| Sorted grid / diagonals | position to (row, column), or `r + c` | search a 2D matrix, diagonal traverse |

## The core idea: a grid is a set of coordinates

A grid is not a picture, it is an array of arrays, and each cell has a row and a column you can compute with. A clockwise turn sends `(i, j)` to `(j, n - 1 - i)`. A diagonal is every cell with the same `r + c`. A position in a sorted grid read row by row is `r = Math.floor(p / cols)` and `c = p % cols`.

## Step by step

<Steps>
  <Step title="Write the coordinate rule">
    Where does the cell at `(i, j)` go, or which cells share a property? Test it on a 2 × 2 or 3 × 3 grid.
  </Step>
  <Step title="Pick the loop bounds">
    Is it all cells, only above the diagonal (`j > i`), or the inner cells `1..n-1`? Off-by-one errors live here.
  </Step>
  <Step title="Decide where the new state goes">
    In place needs a trick (swaps, flags in the grid, an encoding). A copy is fine if the statement allows it.
  </Step>
  <Step title="Never mix old and new">
    If every cell must see the old grid, mark changes without applying them until the scan is done.
  </Step>
  <Step title="Try the thin shapes">
    Run it on 1 × n, n × 1 and 1 × 1 grids. Spiral and zeroes bugs show up there first.
  </Step>
</Steps>

## Complexity

| Variant | Time | Extra space |
|---|---|---|
| Rotate in place | O(n²) | O(1) |
| Spiral, diagonals | O(rows × columns) | O(1) beyond the output |
| Marker row and column | O(rows × columns) | O(1) |
| Game of life, encoded | O(rows × columns) | O(1) |
| Sorted grid search | O(log(rows × columns)) | O(1) |

## JavaScript you'll use

<JsRef to={["arrays", "gotchas", "destructuring-spread"]} />

```js
const grid = Array.from({ length: rows }, () => new Array(cols).fill(0)); // each row separate
[m[i][j], m[j][i]] = [m[j][i], m[i][j]];                                  // swap two cells
for (const row of m) row.reverse();                                       // reverse in place
const DIRS = [[0, 1], [1, 0], [0, -1], [-1, 0]];                          // right, down, left, up
const inside = (r, c) => r >= 0 && r < rows && c >= 0 && c < cols;
```

The classic trap is `new Array(rows).fill(new Array(cols).fill(0))`: every row is the **same** array.

<Callout kind="warning">

- Sharing one row across the grid with `fill`.
- Looping `j` over the whole row when transposing, which swaps every pair twice and undoes it.
- Reading `matrix[0].length` on an empty grid.
- Spiral without the `top <= bottom` and `left <= right` checks.
- Updating cells in place while neighbours still need the old values.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="How do you rotate a non-square grid?">
    You cannot do it in place, because the shape changes from m × n to n × m. Allocate the new grid and copy each `(i, j)` to `(j, m - 1 - i)`.
  </FollowUp>
  <FollowUp q="How would you rotate 90 degrees without transposing?">
    Rotate in rings: for each layer and offset, cycle four cells (top, right, bottom, left). Same O(n²) time and O(1) space, but the index arithmetic is easier to get wrong.
  </FollowUp>
  <FollowUp q="Game of Life on an unbounded board?">
    Store only the live cells in a set. Count neighbours for live cells and their neighbours, so the cost depends on the number of live cells, not the board size.
  </FollowUp>
  <FollowUp q="What if rows and columns are sorted, but rows do not chain?">
    Start at the top-right corner: if the value is too big go left, if too small go down. That is O(rows + columns), and a binary search per row costs O(rows × log columns).
  </FollowUp>
  <FollowUp q="How would you store a huge sparse matrix?">
    Keep a map from `(row, column)` to value, or compressed rows. Memory scales with the non-zero cells, and transposing becomes swapping the key pair.
  </FollowUp>
</FollowUps>
