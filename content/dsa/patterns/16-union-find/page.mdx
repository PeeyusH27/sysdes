## The core idea: one root per group

Picture friend groups. Each group has one **leader**. Everyone points to a friend, and following friends ends at the leader. Are two people in the same group? Compare their leaders. To merge two groups, one leader starts following the other.

The only slow part is climbing to the leader, and that depends on how tall the tree is. Two tricks keep trees flat:

- **Union by rank**: hang the shorter tree under the taller one, so trees stay short.
- **Path compression**: after a climb, point everyone you passed straight at the leader.

Watch the badges (each node's leader). Edge 3-0 is rejected: both ends share leader 0. Try your own edges with Edit input.

<AlgoViz trace={unionByRank} />

With both tricks, each step is close to O(1), so you can treat it as constant.

## Step by step

<Steps>
  <Step title="Decide what the items are">
    Number them `0 … n - 1` (grid cells as `r * cols + c`), or use a `Map`.
  </Step>
  <Step title="Decide what links two items">
    An edge, a shared email, `a == b`: one `union` each.
  </Step>
  <Step title="Start with everyone alone">
    `parent[i] = i`, `rank[i] = 0`, `count = n`.
  </Step>
  <Step title="Union every link">
    `true`: merged, lower the count. `false`: already connected, so the edge closes a cycle.
  </Step>
  <Step title="Read answers through find">
    Use `count` or `find(a) === find(b)`. Never `parent[i]`: a parent is not always a root.
  </Step>
</Steps>

## Complexity

| Version | find / union | Space |
|---|---|---|
| Both tricks | almost O(1) | O(n) |
| One trick only | O(log n) | O(n) |
| Neither | O(n): trees become chains | O(n) |

Kruskal's MST is dominated by sorting: O(E log E).

## JavaScript you'll use

<JsRef to={["classes", "arrays", "map-set"]} />

```js
const parent = Array.from({ length: n }, (_, i) => i); // [0, 1, 2, …, n - 1]
const rank = new Array(n).fill(0);
[ra, rb] = [rb, ra];                                    // swap so ra is the taller root
const id = (r, c) => r * cols + c;                      // grid cell → item number
const uf = new UnionFind(n + 1);                        // labels 1 … n: one extra slot
```

The trap: a recursive `find` on a long chain throws `RangeError: Maximum call stack size exceeded`.

<Callout kind="warning">

- Linking the items instead of their roots: `parent[a] = b` cuts `a` out of its tree.
- Lowering `count` when `union` returned `false`.
- Labels that start at 1: allocate `n + 1` slots.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="Union-find or BFS/DFS for connected components?">
    On a fixed graph both are linear. Union-find wins when edges **arrive over time**: each answer is near-instant, where BFS would start again.
  </FollowUp>
  <FollowUp q="Can union-find remove an edge?">
    Not directly. If you know all queries, run them **in reverse** so deletions become additions.
  </FollowUp>
  <FollowUp q="How do you find the size of the largest group?">
    Union by size: add the smaller size to the larger root on each merge, and track the maximum.
  </FollowUp>
  <FollowUp q="How does Kruskal's algorithm use union-find?">
    Sort edges by weight. Take an edge only if `union(a, b)` returns `true`. Stop at n - 1 edges.
  </FollowUp>
</FollowUps>
