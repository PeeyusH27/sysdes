<TLDR>
A trie stores words **letter by letter along paths from the root**, so words with the same start share nodes. Insert, lookup and prefix checks cost **O(L)** for a word of length L, however many words are stored.
</TLDR>

## When to reach for it

<Callout kind="tip" title="Spot it in the problem statement">

- Many **prefix** questions: "does any word start with…", autocomplete.
- A **dictionary** matched against a sentence, a grid or a stream, giving up when no word can match.
- **Wildcards** such as `.` for "any letter".

</Callout>

| Variant | What you do |
|---|---|
| Basic trie | `children` + an end flag; insert, search, startsWith |
| Prefix walk, early stop | stop at the first end flag or missing edge |
| Wildcard DFS | a `.` tries every child |
| Trie-guided backtracking | a grid DFS moves a trie pointer in step |

## The core idea: a prefix is a path

Think of the thumb tabs on a paper dictionary: every word starting with "ca" sits behind the same two tabs. A trie works the same way. Each node **stands for a prefix**, the letters on the path from the root. Inserting "car" makes (or reuses) root → c → a → r, and **marks** the last node as a word end.

A lookup follows one edge per letter: O(L) whether the trie holds ten words or a million. A hash set is also O(L) per word, but can't answer "does any word start with `ca`?" without scanning them all.

## Choosing the node shape

| Children stored as | Find a child | Memory per node | Watch out for |
|---|---|---|---|
| `Map` | `children.get(ch)`, hashing | only existing children, any character | `get` returns `undefined`, not `null` |
| plain object | `children[ch]` | only existing children, any character | use `Object.create(null)` against inherited keys |
| array of 26 | `next[code - 97]`, no hashing | always 26 slots, `a` to `z` only | other characters index out of range |

An array is fastest; a `Map` is the safe default.

## Complexity

| Operation | Time | Extra space |
|---|---|---|
| Insert one word | O(L) | up to L new nodes |
| `search`, `startsWith` | O(L) | O(1) |
| Build from all words | O(total letters) | O(total letters) nodes (each with 26 slots for arrays) |
| Autocomplete below a prefix | O(L + size of that subtree) | O(depth) for the DFS |
| Wildcard search | O(L) without dots; with many, every node to depth L | O(L) recursion |
| Text scan from every position | O(n · longest word) at most, far less with pruning | O(1) besides the trie |

## JavaScript you'll use

```js
class TrieNode {
  constructor() { this.children = new Map(); this.isEnd = false; }
}
let child = node.children.get(ch);          // undefined when the edge is missing
for (const ch of word) { /* … */ }          // iterate characters
const index = word.charCodeAt(i) - 97;      // 'a' → 0 … 'z' → 25 for array children
for (const [ch, next] of node.children) {}  // DFS over the children that exist
const kids = Object.create(null);           // an object with no inherited keys
```

<Callout kind="warning">

- `search` returning `true` without checking the end flag.
- In wildcard DFS, `return dfs(child, i + 1)` inside the loop: it gives up after the first child.
- In a grid DFS, not marking or restoring a cell.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="Trie or hash set?">
    For exact words, a `Set` is simpler. Pick a trie for prefixes, wildcards or early stopping.
  </FollowUp>
  <FollowUp q="How would you return the top 3 autocomplete suggestions quickly?">
    DFS below the prefix and stop after three, or keep the best 3 on every node.
  </FollowUp>
  <FollowUp q="How do you delete a word?">
    Clear the end flag, then prune childless nodes on the way back up.
  </FollowUp>
  <FollowUp q="How can you make a trie smaller?">
    Merge single-child chains into one edge (a radix tree), or use a ternary search tree.
  </FollowUp>
</FollowUps>
