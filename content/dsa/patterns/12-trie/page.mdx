<TLDR>
A trie stores strings **character by character along paths from the root**, so words with a shared prefix share nodes. Insert, lookup and prefix checks cost **O(L)** for a string of length L, however many words are stored, and a search driven by other input can **stop the moment it leaves the trie**.
</TLDR>

## When to reach for it

<Callout kind="tip" title="Spot it in the problem statement">

- Many **prefix** questions: "does any word start with…", autocomplete, prefix counts.
- A **dictionary** matched against a sentence, a grid or a stream, giving up as soon as no word can match.
- **Wildcards** such as `.` for "any letter".

</Callout>

| Variant | What you do |
|---|---|
| Basic trie | `children` + an end flag; insert, search, startsWith |
| Prefix walk, early stop | stop at the first end flag or missing edge |
| Wildcard DFS | a `.` tries every child |
| Trie-guided backtracking | a grid DFS moves a trie pointer in step |

## The core idea: a prefix is a path

Every node **stands for a prefix**: the characters on the edges from the root down to it. Inserting "car" creates (or reuses) root → c → a → r and **marks** the last node as a word end. After inserting "cart", the "car" node exists either way; only the flag says whether "car" is a word.

A lookup follows one edge per character: O(L), whether the trie holds ten words or a million. A hash set checks a whole word in O(L) too, but it can't answer "does any word start with `ca`?" without scanning every word.

## Step by step

<Steps>
  <Step title="Pick a node shape">
    Children keyed by character, plus an end flag (or, for grid problems, the whole word).
  </Step>
  <Step title="Insert every word">
    Create missing children, mark the last node: O(total characters) to build.
  </Step>
  <Step title="Decide what a query needs at the end">
    A word needs the end flag, a prefix only the path, autocomplete a DFS below it, counting a per-node counter.
  </Step>
  <Step title="Walk the query and stop early">
    One edge per character; return the moment an edge is missing.
  </Step>
  <Step title="Let the trie steer other searches">
    When characters come from a sentence or a grid path, carry a trie node along and abandon dead prefixes.
  </Step>
</Steps>

## Choosing the node shape

| Children stored as | Find a child | Memory per node | Watch out for |
|---|---|---|---|
| `Map` | `children.get(ch)`, hashing | only existing children, any character | `get` returns `undefined`, not `null` |
| plain object | `children[ch]` | only existing children, any character | use `Object.create(null)` against inherited keys |
| array of 26 | `next[code - 97]`, no hashing | always 26 slots, `a` to `z` only | other characters index out of range |

The array is fastest for a small known alphabet; a `Map` is the safe default. Either way each step is O(1).

## Template 2: wildcard search with DFS

At a `.` (any one letter) there are several edges to follow, so the walk becomes a DFS on `(node, index in pattern)`. A letter follows one edge; a dot tries every child and returns `true` at the first branch that matches.

## Template 3: prune a search with the trie

The big wins come when **another search** produces the characters: scan a text from each start, or walk grid paths, moving a trie pointer along. At each step:

- **no child** for the next character: no word continues, so stop this branch;
- the node **ends a word**: record a match, and keep going for longer words.

## Complexity

N is the number of words, S their total length, L the length of one query.

| Operation | Time | Extra space |
|---|---|---|
| Insert one word | O(L) | up to L new nodes |
| `search`, `startsWith` | O(L) | O(1) |
| Build from N words | O(S) | O(S) nodes (each with 26 slots for arrays) |
| Autocomplete below a prefix | O(L + size of that subtree) | O(depth) for the DFS |
| Wildcard search | O(L) without dots; with many, every node to depth L | O(L) recursion |
| Text scan from every position | O(n · longest word) at most, far less with pruning | O(1) besides the trie |

## JavaScript you'll use

<JsRef to={["classes", "map-set", "strings"]} />

```js
class TrieNode {
  constructor() { this.children = new Map(); this.isEnd = false; }
}
let child = node.children.get(ch);          // undefined when the edge is missing
for (const ch of word) { /* … */ }          // iterate characters
const index = word.charCodeAt(i) - 97;      // 'a' → 0 … 'z' → 25 for array children
for (const [ch, next] of node.children) {}  // DFS over the children that exist
const kids = Object.create(null);           // an object with no inherited keys
```

`path + ch` in a hot DFS creates a string per node: fine for autocomplete, but in a grid search read the word from its end node.

<Callout kind="warning">

- `search` returning `true` because the path exists, without checking the end flag.
- In wildcard DFS, `return dfs(child, i + 1)` inside the loop: it gives up after the first child.
- In a grid DFS, not marking a cell as visited, or not restoring it when backtracking.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="Trie or hash set?">
    For exact words, a `Set` is simpler, smaller and also O(L). Pick a trie for prefixes, wildcards or early stopping, and say the cost: per-node overhead can make it many times larger than the strings.
  </FollowUp>
  <FollowUp q="How would you return the top 3 autocomplete suggestions quickly?">
    DFS below the prefix node alphabetically and stop after three, or keep the best k words on every node during inserts. The second makes queries O(L) for more memory and slower inserts: usually right for a search box.
  </FollowUp>
  <FollowUp q="How do you delete a word?">
    Clear the end flag, then prune on the way back up: remove a child with no children that isn't another word's end. Never remove nodes other words still pass through.
  </FollowUp>
  <FollowUp q="How can you make a trie smaller?">
    Compress single-child chains into one edge labelled with a substring (a radix tree). Or use a ternary search tree (three pointers per node, not 26 slots), or a DAWG that also shares suffixes, for static dictionaries.
  </FollowUp>
</FollowUps>
