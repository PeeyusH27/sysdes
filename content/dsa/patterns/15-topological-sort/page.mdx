<TLDR>
A **topological order** lists a directed graph's nodes so every edge points forward, and one exists exactly when there is **no cycle**. **Kahn's algorithm** keeps taking a node with no incoming edges left; **DFS** reverses the order in which nodes finish. Both are O(V + E) and catch cycles for free.
</TLDR>

## When to reach for it

<Callout kind="tip" title="Spot it in the problem statement">

- **Prerequisites, dependencies, "must happen before"**: courses, build steps, package installs.
- "Return **an order** in which…", "is it **possible to finish**…", "does this **directed** graph have a **cycle**?"
- The **minimum number of rounds or semesters** when independent tasks run in parallel.
- An order **inferred** from comparisons: an alien alphabet from sorted words.

</Callout>

| Variant | Reports a cycle when | Classic problems |
|---|---|---|
| Kahn's algorithm (BFS) | fewer than V nodes are placed | course schedule, alien dictionary |
| Kahn's, level by level | same | parallel courses, build stages |
| DFS with three colours | an edge reaches a gray node | course schedule II, cycle detection |
| Kahn's on reversed edges | leftovers are on, or lead into, a cycle | eventual safe states |

## The core idea: start with something that has no prerequisites

Draw `u → v` for "u before v". A graph **without** a cycle always has a node with **no incoming edges** (otherwise you could walk backwards forever and must revisit a node: a cycle). That node goes first. Remove it and its edges; the rest is still acyclic, so repeat.

Kahn's algorithm counts each node's **in-degree** (incoming edges from unplaced nodes) and queues the nodes at 0. Placing a node decrements the nodes it points to; any that reach 0 join the queue. Try your own edges, a cycle included, with Edit input.

<AlgoViz trace={kahn} />

**Why a leftover node means a cycle.** If the queue empties early, every leftover node has an incoming edge from another leftover node; walk backwards and you must revisit one. Conversely, nodes on a cycle wait for each other, so none reaches 0. The check is one line: `order.length === n`.

## Step by step

<Steps>
  <Step title="Fix the edge direction">
    Decide that `u → v` means "u before v", and translate carefully. In Course Schedule, `[a, b]` means **b** before **a**, so the edge is `b → a`; backwards silently reverses the answer.
  </Step>
  <Step title="Build the adjacency list and the in-degrees">
    One pass: `adj[u].push(v)` and `indegree[v]++`. Include nodes without edges: they still need a place.
  </Step>
  <Step title="Seed the queue">
    Push every node with in-degree 0. None in a non-empty graph means a cycle.
  </Step>
  <Step title="Take, append, release">
    Pop a node and append it to the order. Decrement each node it points to; push the ones that reach 0.
  </Step>
  <Step title="Check for leftovers">
    All V placed: a valid order. Otherwise return the "impossible" value: `false`, `[]`, `-1` or `""`.
  </Step>
</Steps>

## Template 1: Kahn's algorithm

The default. It is iterative, so a long chain can't overflow the stack; it builds the order directly; and the cycle check is a length comparison. It solves <ProblemLink slug="course-schedule" />, <ProblemLink slug="course-schedule-ii" /> and, once you've built the letter graph, <ProblemLink slug="alien-dictionary" />.

Most graphs have many valid orders; Kahn's returns one, depending on how nodes are seeded and edges listed. For the **smallest** order in dictionary order, swap the queue for a min-heap.

## Template 2: DFS with three colours

DFS works from the other end. A node **finishes** only after everything reachable from it, so reversing the finishing order points every edge forward.

Cycle detection needs **three** states, not two:

- **white**: not visited yet;
- **gray**: on the current path, entered but not finished;
- **black**: finished, along with everything reachable from it.

An edge into a **gray** node goes back up the current path: a cycle. An edge into a **black** node is harmless and common (two courses sharing a prerequisite). A plain visited set can't tell them apart.

<CodeTabs files={['snippets/dfs-topo.js']} java={['snippets/java/DfsTopo.java']} python={['snippets/python/dfs_topo.py']} />

Colours also answer "which nodes can reach a cycle?", the DFS route to <ProblemLink slug="find-eventual-safe-states" />: a node is safe when its DFS finishes black without meeting gray.

## Template 3: Kahn's, level by level

When independent tasks run in parallel, process the queue in **rounds**: every node at in-degree 0 right now is one round, and placing them releases the next. The number of rounds is the minimum number of semesters, equal to the nodes on the longest chain: <ProblemLink slug="parallel-courses" />.

<CodeTabs files={['snippets/kahn-levels.js']} java={['snippets/java/KahnLevels.java']} python={['snippets/python/kahn_levels.py']} />

Run Kahn's on the **reversed** graph, counting out-degrees, and you peel nodes off from the dead ends. Every peeled node can't reach a cycle: the other way to solve <ProblemLink slug="find-eventual-safe-states" />.

## Complexity

| Algorithm | Time | Extra space |
|---|---|---|
| Kahn's algorithm | O(V + E): each node queued once, each edge decremented once | O(V + E) |
| DFS with three colours | O(V + E) | O(V + E), plus recursion up to V deep |
| Kahn's, level by level | O(V + E) | O(V + E) |
| Letter graph in Alien Dictionary | O(C) for C characters in total | O(1): at most 26 letters, 26² edges |

## JavaScript you'll use

<JsRef to={["graphs-in-js", "stack-queue-deque", "map-set"]} />

```js
const adj = Array.from({ length: n }, () => []);
const indegree = new Array(n).fill(0);
for (const [from, to] of edges) { adj[from].push(to); indegree[to]++; }
const queue = [];
for (let v = 0; v < n; v++) if (indegree[v] === 0) queue.push(v);
for (let head = 0; head < queue.length; head++) { /* queue[head] is the next node of the order */ }
const after = new Map();                                // letter → Set of letters that come after it
if (!after.get(a).has(b)) { after.get(a).add(b); indegree.set(b, indegree.get(b) + 1); }
```

With a head-index queue, the queue **is** the order at the end. With string nodes, don't count an edge twice in the in-degree while the Set stores it once: that node never reaches 0, and you report a phantom cycle.

<Callout kind="warning">

- Returning a partial order when there's a cycle, instead of the "impossible" value.
- Forgetting to reverse the DFS finishing order (or reversing it when you followed edges backwards).
- 1-based labels with arrays of size n: `indegree[n]` is `undefined`, and `undefined + 1` is `NaN`.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="Kahn's algorithm or DFS: which would you pick?">
    Kahn's by default: iterative (a 10,000-node chain can't overflow the stack), a one-line cycle check, and rounds for free. DFS is shorter if you already have it, and its colours show **which** nodes are on or behind a cycle.
  </FollowUp>
  <FollowUp q="How would you return the cycle itself, not just report that one exists?">
    Use three-colour DFS with a parent array. When `u → v` reaches gray `v`, follow parents from `u` back to `v`: that path plus the edge is the cycle. Kahn's leftovers also include nodes that merely sit behind it.
  </FollowUp>
  <FollowUp q="When is the topological order unique, and how can you check?">
    When every step is forced: Kahn's queue never holds more than one node. Equivalently, consecutive nodes in the order are all joined by edges, which is what "reconstruct the sequence uniquely" problems test.
  </FollowUp>
  <FollowUp q="Dependencies arrive one at a time, and you must report a cycle as soon as one appears. What changes?">
    A new edge `u → v` closes a cycle exactly when `v` already reaches `u`: one search from `v`, not a full O(V + E) re-sort. For **undirected** graphs union-find does it in near-constant time (see [Union-Find](/dsa/patterns/union-find)), but it ignores direction.
  </FollowUp>
  <FollowUp q="Tasks have durations and independent ones run in parallel. How long does the whole project take?">
    In topological order, `finish[v] = duration[v] + max(finish[u])` over prerequisites `u` (0 if none), and the answer is the largest `finish`: the **critical path**, in O(V + E). With all durations 1 it equals the number of Kahn's rounds.
  </FollowUp>
</FollowUps>
