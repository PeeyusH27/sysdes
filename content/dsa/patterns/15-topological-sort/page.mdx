<TLDR>
A **topological order** lists a directed graph's nodes so every edge points forward. One exists exactly when there is **no cycle**. **Kahn's algorithm** keeps taking a node with nothing left before it. Kahn's and DFS are both O(V + E) and catch cycles.
</TLDR>

## The core idea: start with something that has no prerequisites

Think of getting dressed: socks before shoes, shirt before jacket. Draw `u → v` for "u before v". You can always start with something that has **nothing pointing at it**, like the socks. Put it first, cross it off, and repeat. If you run out of such things while some remain, they are waiting on each other: a **cycle**.

Kahn's algorithm keeps a count of each node's unmet prerequisites (its **in-degree**) and queues the nodes at 0. Placing a node lowers the count of the nodes it points to; any that hit 0 join the queue.

<AlgoViz trace={kahn} />

The cycle check is one line: `order.length === n`.

## Step by step

<Steps>
  <Step title="Fix the edge direction">
    `u → v` means "u before v". In Course Schedule, `[a, b]` means **b** before **a**, so the edge is `b → a`.
  </Step>
  <Step title="Build the adjacency list and the in-degrees">
    `adj[u].push(v)` and `indegree[v]++`. Include nodes without edges.
  </Step>
  <Step title="Seed the queue">
    Push every node with in-degree 0.
  </Step>
  <Step title="Take, append, release">
    Pop a node, append it, lower its neighbours' counts, push any that reach 0.
  </Step>
  <Step title="Check for leftovers">
    All V placed: a valid order. Otherwise return the "impossible" value.
  </Step>
</Steps>

## Template 1: Kahn's algorithm

The default. It is iterative, builds the order directly, and checks for a cycle with a length comparison. It solves <ProblemLink slug="course-schedule" />, <ProblemLink slug="course-schedule-ii" /> and <ProblemLink slug="alien-dictionary" />.

Most graphs have many valid orders; Kahn's returns one. For the **smallest** order, swap the queue for a min-heap.

## Template 2: DFS with three colours

A node **finishes** only after everything reachable from it, so reversing the finishing order points every edge forward. To catch cycles, mark nodes in **three** states:

- **white**: not visited;
- **gray**: on the current path;
- **black**: finished.

An edge into a **gray** node goes back up the current path: a cycle. An edge into a **black** node is harmless.

## Template 3: Kahn's, level by level

When independent tasks run in parallel, process the queue in **rounds**: everything at in-degree 0 right now is one round. The number of rounds is the minimum number of semesters: <ProblemLink slug="parallel-courses" />.

## Complexity

| Algorithm | Time | Extra space |
|---|---|---|
| Kahn's algorithm | O(V + E): each node queued once, each edge decremented once | O(V + E) |
| DFS with three colours | O(V + E) | O(V + E), plus recursion up to V deep |
| Kahn's, level by level | O(V + E) | O(V + E) |
| Letter graph in Alien Dictionary | O(C) for C characters in total | O(1): at most 26 letters, 26² edges |

## JavaScript you'll use

<JsRef to={["graphs-in-js", "stack-queue-deque", "map-set"]} />

```js
const adj = Array.from({ length: n }, () => []);
const indegree = new Array(n).fill(0);
for (const [from, to] of edges) { adj[from].push(to); indegree[to]++; }
const queue = [];
for (let v = 0; v < n; v++) if (indegree[v] === 0) queue.push(v);
for (let head = 0; head < queue.length; head++) { /* queue[head] is the next node of the order */ }
const after = new Map();                                // letter → Set of letters that come after it
if (!after.get(a).has(b)) { after.get(a).add(b); indegree.set(b, indegree.get(b) + 1); }
```

With string nodes, don't count an edge twice in the in-degree while the Set stores it once: you will report a phantom cycle.

<Callout kind="warning">

- Returning a partial order when there is a cycle.
- Forgetting to reverse the DFS finishing order.
- 1-based labels with arrays of size n: `indegree[n]` is `undefined`.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="Kahn's algorithm or DFS?">
    Kahn's by default: iterative, a one-line cycle check, rounds for free. DFS colours show **which** nodes are on a cycle.
  </FollowUp>
  <FollowUp q="How would you return the cycle itself?">
    Three-colour DFS with a parent array. When an edge hits a gray node, follow parents back to it.
  </FollowUp>
  <FollowUp q="When is the topological order unique?">
    When Kahn's queue never holds more than one node.
  </FollowUp>
  <FollowUp q="Dependencies arrive one at a time. How do you spot a cycle at once?">
    A new edge `u → v` closes a cycle exactly when `v` already reaches `u`: search from `v`.
  </FollowUp>
  <FollowUp q="Tasks have durations. How long does the whole project take?">
    In topological order, `finish[v] = duration[v] + max(finish[u])` over prerequisites `u`. The largest `finish` is the **critical path**.
  </FollowUp>
</FollowUps>
