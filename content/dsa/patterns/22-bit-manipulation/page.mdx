<TLDR>
A number is a row of switches (bits), and one operator flips many at once. Three tricks cover most questions: **XOR cancels pairs**, **`n & (n - 1)` drops the lowest 1**, and **masks** test one switch.
</TLDR>

## When to reach for it

<Callout kind="tip" title="Spot it in the problem statement">

- "Every element appears **twice except one**", or a number is **missing** from a range, in O(1) space: XOR.
- **Count set bits** or test for a **power of two**: `n & (n - 1)`.
- Arithmetic **without `+` or `-`**: XOR plus a carry.
- Every **subset** of a small set (n up to about 20): masks.

</Callout>

## The core idea: one operator, every bit at once

Picture a panel of switches. An operator works on the whole row in a single step, no loop.

| Operator | Example on 4 bits | Typical use |
|---|---|---|
| `a & b` (AND) | `1100 & 1010 = 1000` | test a bit |
| `a \| b` (OR) | `1100 \| 1010 = 1110` | set bits |
| `a ^ b` (XOR) | `1100 ^ 1010 = 0110` | toggle, cancel pairs |
| `1 << i` | `1 << 2 = 0100` | build a mask for bit `i` |

XOR is the star. `x ^ x` is 0 and `x ^ 0` is `x`, so XOR a whole list and every pair cancels. Only the unpaired value survives:

<AlgoViz trace={xorAccumulate} />

**JavaScript's 32-bit rule.** Bitwise operators work on **signed 32-bit** integers, so bit 31 is the sign. Use `x >>> 0` to read the bits as unsigned, and `BigInt` for wider values.

## Step by step

Bit bugs are silent, so work in this order.

<Steps>
  <Step title="Write small cases in binary">
    3 to 6 inputs in 4-bit binary, aligned by column. Patterns jump out.
  </Step>
  <Step title="Mind the 32-bit rule">
    Use `>>>` on unsigned input and `>>> 0` when the answer may reach 2^31.
  </Step>
  <Step title="Add parentheses">
    `&`, `|` and `^` bind **more loosely** than `===`. Write `(n & 1) === 0`.
  </Step>
  <Step title="Test the edges">
    0, 1, a power of two, all ones, and a negative if allowed.
  </Step>
</Steps>

## Complexity

| Task | Time | Space |
|---|---|---|
| One bitwise operation | O(1) | O(1) |
| XOR over n values | O(n) | O(1) |
| Popcount with `n & (n - 1)` | at most 32 steps | O(1) |
| All subsets of n items | O(n · 2^n) | O(n · 2^n) |

## JavaScript you'll use

<JsRef to={["bitwise", "numbers-math"]} />

```js
(n >> i) & 1               // bit i of n: 0 or 1
n | (1 << i)               // set bit i
n & ~(1 << i)              // clear bit i
n & (n - 1)                // n without its lowest set bit
n & -n                     // only the lowest set bit
x >>> 0                    // the same 32 bits, read as unsigned
~x                         // flips every bit: ~5 is -6
(13).toString(2)           // "1101": binary for debugging
parseInt("1101", 2)        // 13
```

<Callout kind="warning">

- Returning a result with bit 31 set without `>>> 0`: it comes out negative.
- Treating `~` as logical NOT: `~0` is `-1`, which is truthy.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="Every number appears three times except one. XOR no longer cancels: what now?">
    Count the 1s in each of the 32 columns. Triples add a multiple of 3, so `count % 3` is the single number's bit.
  </FollowUp>
  <FollowUp q="Two numbers appear once and all others twice. How do you find both?">
    XOR everything to get `a ^ b`, and take a set bit of it. Split the array by that bit and XOR each half.
  </FollowUp>
  <FollowUp q="How do you check whether n is a power of two?">
    `n > 0 && (n & (n - 1)) === 0`: exactly one set bit.
  </FollowUp>
  <FollowUp q="When would you store a set as a bitmask instead of a Set?">
    When the universe is small and fixed. Union is `|`, intersection is `&`, and the whole set is one number you can use as a memo key.
  </FollowUp>
</FollowUps>
