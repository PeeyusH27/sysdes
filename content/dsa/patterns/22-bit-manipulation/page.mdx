<TLDR>
An integer is a row of bits, and one bitwise operator changes them all in O(1). Three tricks cover most questions: **XOR cancels pairs**, **`n & (n - 1)` drops the lowest set bit**, and **masks** built with `1 << i` test, set or clear one bit.
</TLDR>

## When to reach for it

<Callout kind="tip" title="Spot it in the problem statement">

- "Every element appears **twice except one**", or a number is **missing** from a range, in O(1) extra space: XOR.
- **Count set bits** or test for a **power of two**: `n & (n - 1)`.
- Arithmetic **without `+`, `-`, `*` or `/`**: XOR plus a carry.
- Every **subset** of a small set (n up to about 20), or "which items are used" as one number: masks.
- The input is **32-bit unsigned**, or a row of bits or flags.

</Callout>

## The core idea: one operator, every bit at once

A bitwise operator doesn't loop over bits: it handles every column in one step.

| Operator | Example on 4 bits | Typical use |
|---|---|---|
| `a & b` (AND) | `1100 & 1010 = 1000` | test a bit, keep only a mask's bits |
| `a \| b` (OR) | `1100 \| 1010 = 1110` | set bits |
| `a ^ b` (XOR) | `1100 ^ 1010 = 0110` | toggle bits, cancel pairs |
| `~a` (NOT) | `~5 === -6` | flip every bit; `~x` equals `-x - 1` |
| `a << k` | `0011 << 2 = 1100` | multiply by 2^k, build the mask `1 << i` |
| `a >> k` | `-8 >> 1 === -4` | divide by 2^k rounding down, keeping the sign |
| `a >>> k` | `-1 >>> 0 === 4294967295` | treat the 32 bits as unsigned |

XOR is the star. `x ^ x` is 0, `x ^ 0` is `x` and order doesn't matter, so in a XOR of a whole list every pair cancels and only the unpaired value survives. Each result bit is the **parity** of its column:

<AlgoViz trace={xorAccumulate} />

**JavaScript's 32-bit rule.** Numbers are 64-bit floats, but bitwise operators work on **signed 32-bit** integers:

- Bit 31 is the sign bit: `1 << 31` is `-2147483648`, and `4294967295` reads as `-1`.
- `x >>> 0` reads the 32 bits as unsigned (0 to 2^32 - 1): use it when bit 31 may be set.
- Wider values are cut (`2 ** 32 | 0` is 0) and fractions dropped (`7.9 | 0` is 7). For more bits, use `BigInt`: `1n << 40n`.

## Step by step

Bit bugs are silent, so work in this order.

<Steps>
  <Step title="Write small cases in binary">
    3 to 6 inputs in 4- or 8-bit binary, aligned by column. Pairs, parity and "lowest 1" patterns jump out.
  </Step>
  <Step title="Mind the 32-bit rule">
    `>>>` on unsigned input, a final `>>> 0` when the answer may reach 2^31, and shifts below 32: `1 << 32` is 1, because the count is taken modulo 32.
  </Step>
  <Step title="Add parentheses">
    `&`, `|` and `^` bind **more loosely** than `===` and `<`. Write `(n & 1) === 0`, never `n & 1 === 0`.
  </Step>
  <Step title="Test the edges">
    0, 1, a power of two, all ones (2^31 - 1, or 2^32 - 1 unsigned), and a negative if allowed.
  </Step>
</Steps>

## Template 3: drop the lowest set bit

Subtracting 1 turns the lowest 1 into 0 and the 0s under it into 1s, leaving higher bits alone. AND with `n` keeps the higher bits and wipes the rest: `n` loses its lowest set bit, and a loop runs once per set bit. Try your own `n` with Edit input:

## Complexity

| Task | Time | Extra space |
|---|---|---|
| Any single bitwise operation | O(1) | O(1) |
| XOR over n values | O(n) | O(1) |
| Popcount with `n & (n - 1)` | O(number of set bits), at most 32 | O(1) |
| Counting bits for 0 … n | O(n) | O(n) for the output |
| Reversing 32 bits | O(32) = O(1) | O(1) |
| All subsets of n items | O(n · 2^n) | O(n · 2^n) for the output |

## JavaScript you'll use

<JsRef to={["bitwise", "numbers-math"]} />

```js
(n >> i) & 1               // bit i of n: 0 or 1
n | (1 << i)               // set bit i
n & ~(1 << i)              // clear bit i
n & (n - 1)                // n without its lowest set bit
n & -n                     // only the lowest set bit
x >>> 0                    // the same 32 bits, read as unsigned
(13).toString(2)           // "1101": binary for debugging
parseInt("1101", 2)        // 13
```

<Callout kind="warning">

- Returning a result with bit 31 set without `>>> 0`: it comes out negative.
- Treating `~` as logical NOT: `~0` is `-1`, which is truthy.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="Every number appears three times except one. XOR no longer cancels: what now?">
    Count the 1s in each of the 32 columns: triples add a multiple of 3, so `count % 3` is the single number's bit. Rebuild it with `result |= 1 << i` in O(32 · n) time and O(1) space.
  </FollowUp>
  <FollowUp q="Two numbers appear once and all others twice. How do you find both?">
    XOR everything to get `a ^ b` (non-zero, since they differ) and take a set bit, such as `x & -x`. Split the array by that bit and XOR each half: pairs stay together, so each half yields one answer.
  </FollowUp>
  <FollowUp q="How do you check whether n is a power of two, or a power of four?">
    Power of two: `n > 0 && (n & (n - 1)) === 0` (exactly one set bit). Power of four: also `(n & 0x55555555) !== 0`, so the bit sits at an even position, or equivalently `n % 3 === 1`.
  </FollowUp>
  <FollowUp q="When would you store a set as a bitmask instead of a Set?">
    When the universe is small and fixed (up to 31 items in a plain number). Union is `|`, intersection is `&`, and the whole set is one number, so it's a memo key: that's what makes bitmask DP over 2^n states practical up to n ≈ 20.
  </FollowUp>
  <FollowUp q="How do you handle 64-bit values in JavaScript?">
    `BigInt`: literals end in `n` and every operator works (`1n << 40n`), but it can't mix with plain numbers and it's slower. `BigInt.asUintN(64, x)` wraps a result to 64 unsigned bits; the alternative is two 32-bit halves.
  </FollowUp>
</FollowUps>
