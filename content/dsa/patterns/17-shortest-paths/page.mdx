<TLDR>
Every shortest-path algorithm repeats one move, **relaxation**: if going through `u` is cheaper, lower `dist[v]`. Only the order differs: **BFS** for equal edges, **Dijkstra** for non-negative weights, **Bellman-Ford** for negative ones.
</TLDR>

## The core idea: relax, closest first

Picture a road trip. Every town has a sign: "cheapest known cost to get here". That sign is `dist[v]`, `Infinity` everywhere except the start. To **relax** `u → v` with weight `w`, ask: is `dist[u] + w` less than `dist[v]`? If so, fix the sign.

Dijkstra adds one rule: **always visit the town with the smallest sign next**. Once it is picked, its sign is final. Any other route is already at least as long, and edges never subtract.

JavaScript has no decrease-key heap, so push a fresh `[dist, v]` on each improvement and skip old entries when they surface (`d > dist[u]`). Watch B, D, E and F get stale entries:

### Why negative edges break Dijkstra

Take `A → B` costing 4, `A → C` 5 and `C → B` -3. Dijkstra settles B at 4, but `A → C → B` costs 2. Its rule needs edges that never make a route cheaper, so use Bellman-Ford. With a **negative cycle**, no shortest path exists: one more lap is always cheaper.

## Step by step

<Steps>
  <Step title="Model the graph">
    Nodes are cities, cells or states. Build `adj[u]` as `[v, w]` pairs.
  </Step>
  <Step title="Pick the algorithm from the weights">
    Equal: BFS. Non-negative: Dijkstra. Negative, or an edge limit: Bellman-Ford.
  </Step>
  <Step title="Define how a route's cost combines">
    Usually `dist[u] + w`. For effort, `Math.max(dist[u], step)`.
  </Step>
  <Step title="Initialise">
    `dist` full of `Infinity`, `dist[source] = 0`.
  </Step>
  <Step title="Relax until nothing changes">
    Pop, skip stale, relax, push. Stop when the target is **popped**.
  </Step>
  <Step title="Read the answer">
    `dist[target]`, or `-1` if still `Infinity`.
  </Step>
</Steps>

## Template 3: Bellman-Ford, round by round

Each round relaxes **every** edge, reading last round's distances and writing a copy. After round `r`, `dist[v]` is the cheapest path with **at most `r` edges**. So `n - 1` rounds suffice.

## Complexity

| Algorithm | Time | Space |
|---|---|---|
| BFS | O(V + E) | O(V) |
| Dijkstra with a heap | O(E log V) | O(V + E) |
| Bellman-Ford | O(V · E) | O(V) |

Dijkstra with an array scan is O(V²), better on dense graphs. Floyd–Warshall (all pairs) is O(V³).

## JavaScript you'll use

<JsRef to={["heap", "graphs-in-js", "stack-queue-deque"]} />

```js
const adj = Array.from({ length: n }, () => []);   // one fresh list per node
for (const [u, v, w] of edges) adj[u].push([v, w]);
const dist = new Array(n).fill(Infinity);           // Infinity + w is still Infinity
const [d, u] = heap.pop();                          // entries are [distance, node]
const next = dist.slice();                          // Bellman-Ford: read old, write new
const DIRS = [[1, 0], [-1, 0], [0, 1], [0, -1]];    // grid neighbours
```

The real trap is the missing priority queue. Re-sorting on every push, or `queue.shift()`, wrecks the complexity.

<Callout kind="warning">

- Freezing a node on push: only a pop is final.
- `new Array(n).fill([])`: every node shares one list.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="How do you return the path itself, not just its cost?">
    Set `prev[v] = u` on every improvement. Walk `prev` back from the target and reverse.
  </FollowUp>
  <FollowUp q="Edges cost either 0 or 1. Can you beat Dijkstra?">
    Yes: 0-1 BFS puts 0-edges at the **front** of a deque and 1-edges at the **back**. No heap, O(V + E).
  </FollowUp>
  <FollowUp q="How would you detect a negative cycle?">
    Run one more Bellman-Ford pass after n - 1 rounds. An edge that still relaxes means a negative cycle.
  </FollowUp>
  <FollowUp q="You need shortest paths between every pair. What would you do?">
    Small and dense: Floyd–Warshall, O(V³). Large and sparse: Dijkstra from every node.
  </FollowUp>
  <FollowUp q="Dijkstra is too slow for one A-to-B query on a huge map. What now?">
    Stop when B is popped, search from both ends, or use A*, which orders the heap by `dist[v]` plus a straight-line guess to B.
  </FollowUp>
</FollowUps>
