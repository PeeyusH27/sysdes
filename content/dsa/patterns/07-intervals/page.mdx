## The core idea: sorting makes overlap local

Picture meetings as bars on a calendar. Two overlap when **each starts before the other ends**. A meeting ending at 3 and one starting at 3 do not clash.

Checking every pair is O(n²). **Sort by start** and only neighbours matter: once an interval starts after the current group ends, every later one does too, so the group is final. Try your own intervals with **Edit input**:

## Step by step

<Steps>
  <Step title="Pin down the overlap rule">
    Do `[1, 3]` and `[3, 5]` overlap? Decide before any loop.
  </Step>
  <Step title="Choose the sort key">
    **Start** to merge or find clashes, **end** to keep the most.
  </Step>
  <Step title="Decide what the sweep remembers">
    The open group, a count, or a heap of end times.
  </Step>
  <Step title="Process each interval in one step">
    Extend with `Math.max`: a later interval can sit inside an earlier one.
  </Step>
  <Step title="Flush and check the edges">
    Push the last open group. Test nested and back-to-back intervals.
  </Step>
</Steps>

## Template 2: count how many overlap at once

"How many rooms?" means "how many meetings run at the busiest moment?" That count only changes at a start (+1) or an end (−1). Sort these **events** by time and keep a running sum: the **sweep line**. On ties put −1 first.

## Template 3: keep the most, remove the fewest

Sort by **end** and keep every interval that starts at or after the last kept end. Ending first leaves the most room ([Greedy](/dsa/patterns/greedy)).

```js
intervals.sort((a, b) => a[1] - b[1]);       // earliest end first
let kept = 0, lastEnd = -Infinity;
for (const [start, end] of intervals) {
  if (start >= lastEnd) { kept++; lastEnd = end; }
}
// fewest removals = intervals.length - kept
```

That is <ProblemLink slug="non-overlapping-intervals" />. "Minimum arrows to burst balloons" is the same loop.

## Template 4: two sorted lists

Both lists sorted? One pointer each. Record the intersection, then advance whichever interval **ends first** ([Two Pointers](/dsa/patterns/two-pointers)). See <ProblemLink slug="interval-list-intersections" />.

## Complexity

| Variant | Time | Extra space |
|---|---|---|
| Merge, clash check, keep the most | O(n log n) | O(n) |
| Sweep line, or start order plus min-heap | O(n log n) | O(n) |
| Two sorted lists | O(n + m) | O(n + m) |

## JavaScript you'll use

<JsRef to={["sorting", "destructuring-spread", "heap"]} />

```js
intervals.sort((a, b) => a[0] - b[0]);              // by start; sort() alone compares "10,12" < "9,10"
const sorted = [...intervals].sort((a, b) => a[1] - b[1]); // by end, without reordering the input
events.sort((a, b) => a[0] - b[0] || a[1] - b[1]);  // by time, then -1 before +1
for (const [start, end] of sorted) { /* … */ }      // unpack each pair
const last = merged.at(-1);                          // the open group
last[1] = Math.max(last[1], end);                    // mutate it in place: it's the same array
```

<Callout kind="warning">

- `intervals.sort()` with no comparator compares arrays as strings.
- Processing a start before an end at the same time counts one room too many.
- Sorting by start for "keep the most": `[1, 100]` then blocks everything.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="Meeting rooms: sweep line or min-heap?">
    Both O(n log n). The sweep line is shorter for "how many?"; the heap suits assigning rooms or streams.
  </FollowUp>
  <FollowUp q="Intervals arrive one at a time. What changes?">
    Keep merged intervals in a balanced search tree by start: O(log n) per insert.
  </FollowUp>
  <FollowUp q="How would you find free time common to several calendars?">
    Merge everyone's busy intervals, then report the gaps.
  </FollowUp>
  <FollowUp q="The coordinates are small integers. Is there something faster than sorting?">
    A difference array: +1 at the start, −1 at the end, then a prefix sum. See [Prefix Sums](/dsa/patterns/prefix-sum).
  </FollowUp>
</FollowUps>
