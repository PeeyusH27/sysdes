## The core idea: a range that must contain the answer

Guess a number from 1 to 100 and hear "higher" or "lower". Each answer rules out half the numbers.

One sentence holds every binary search together, the **invariant**: *if the answer exists, it is inside `[lo, hi]`.* Each check proves one half can't hold it, so that half goes.

On a sorted array, if `nums[mid]` is smaller than the target, everything left of it is too. The left half goes.

Halving is the speed: 10 checks for a thousand, 20 for a million, 30 for a billion. `mid` rounds **down**, so `lo <= mid < hi` while `lo < hi`. Try your own array with **Edit input**:

## Step by step

<Steps>
  <Step title="Name the search space">
    Indices (up to `n` if "insert at the end" is valid), or answer values.
  </Step>
  <Step title="Write the yes/no question and check it is monotonic">
    `ok(x)` must be false, then true: like `nums[i] >= target`. If `ok(x)` doesn't imply `ok(x + 1)`, it's the wrong tool.
  </Step>
  <Step title="Pick the template and state the invariant">
    First true: "everything before `lo` is false, everything from `hi` on is true".
  </Step>
  <Step title="Update so the range shrinks">
    Never `lo = mid` with a rounded-down `mid`: it loops forever.
  </Step>
  <Step title="Run the tiny cases by hand">
    Trace 0, 1 and 2 candidates.
  </Step>
</Steps>

## Template 2: first true (lower bound)

Most questions aren't "is it here?" but "**where does it start?**": the first copy, the insert position, the first bad version. Picture a yes/no test over the candidates:

```text
index:          0  1  2  3  4  5  6     (7 = "none")
nums:           1  3  3  3  5  8  9
nums[i] >= 3?   F  T  T  T  T  T  T
                   ^ first true = 1
```

`hi` starts at `n`, one past the end, because "nothing passes" is a legal answer.

`lowerBound` answers <ProblemLink slug="search-insert-position" />. For <ProblemLink slug="find-first-and-last-position" />, the first copy is at `lowerBound(x)` and the last at `upperBound(x) - 1`.

**Off-by-one, settled.** The templates come in matched sets:

| Template | Loop | Updates | Ends with |
|---|---|---|---|
| Exact match | `lo <= hi` | `lo = mid + 1`, `hi = mid - 1` | `lo === hi + 1` (empty) |
| First true | `lo < hi` | `lo = mid + 1`, `hi = mid` | `lo === hi` (the answer) |

Mix the parts and `lo <= hi` with `hi = mid` loops forever.

## Template 3: rotated sorted arrays

Rotate `[1, 2, 4, 5, 7, 9]` into `[5, 7, 9, 1, 2, 4]` and plain halving breaks. But cut anywhere and **at least one half is still sorted**. Its two ends tell you whether the target is inside.

## Template 4: binary search on the answer

Nothing is sorted, but the **answer** is a number in a known range, and checking one candidate is cheap. Can every package ship in `days` days with capacity `cap`?

If a candidate works, every bigger one does too. So "does x work?" goes no, no, yes, yes, and first true finds the smallest that works.

## Complexity

| Variant | Time | Extra space |
|---|---|---|
| Exact match, bounds, rotated | O(log n) | O(1) |
| On the answer: range R, each check O(n) | O(n log R) | O(1) |
| Recursive version | same time | O(log n) call stack |

## JavaScript you'll use

<JsRef to={["numbers-math", "arrays"]} />

```js
const mid = Math.floor((lo + hi) / 2);     // exact for any integers up to 2^53
const mid2 = lo + ((hi - lo) >> 1);        // also fine while hi - lo < 2^31
(1500000000 + 1600000000) >> 1;           // -597483648: >> works on 32-bit integers
Math.ceil(pile / speed);                   // hours for a pile: a partial hour counts as one
Math.max(...weights);                      // largest value (spreads every element as an argument)
nums.reduce((a, b) => a + b, 0);           // total, a common upper bound for answer searches
```

`Math.max(...arr)` throws a `RangeError` above about 100,000 elements: use `reduce` for huge inputs.

<Callout kind="warning">

- Starting `hi` at `n - 1` when "past the end" is a valid answer.
- A lower bound returns a position even when the target is missing, so check `nums[i] === target`.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="Do you need lo + (hi - lo) / 2 in JavaScript?">
    No: `Math.floor((lo + hi) / 2)` is exact. The real bug is `(lo + hi) >> 1`, negative past 2.1 billion.
  </FollowUp>
  <FollowUp q="What changes in a rotated array with repeated values?">
    Equal ends hide which half is sorted, so shrink with `lo++` and `hi--`. Worst case O(n).
  </FollowUp>
  <FollowUp q="How do you search for a real-valued answer, like a square root?">
    Use `lo = mid` or `hi = mid`, and stop after a fixed number of rounds.
  </FollowUp>
  <FollowUp q="The sorted array's length is unknown. How do you search it?">
    Probe 1, 2, 4, 8, … until you pass the target, then binary search the last gap.
  </FollowUp>
  <FollowUp q="How do you search a sorted matrix?">
    If each row starts after the last ends, treat it as one sorted array. Otherwise walk from the top-right corner.
  </FollowUp>
</FollowUps>
