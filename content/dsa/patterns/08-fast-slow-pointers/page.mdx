<TLDR>
Two pointers walk one list at different speeds: `slow` one step, `fast` two. When `fast` runs out, `slow` is at the **middle**; in a **loop**, `fast` laps `slow`, and a second walk from the head finds where the loop begins, all in **O(1) extra space**.
</TLDR>

## When to reach for it

<Callout kind="tip" title="Spot it in the problem statement">

- A **linked list** might have a **cycle**, or you need its **middle** without counting first.
- A **sequence defined by a rule** (sum of digit squares, `i → nums[i]`) may repeat forever.
- **O(1) extra space** is required where a visited `Set` would be the easy answer.

</Callout>

| Variant | Pointers | Classic problems |
|---|---|---|
| Find the middle | slow +1, fast +2 | middle of the list, palindrome list |
| Cycle and its entry | +1 and +2 until they meet; then both +1 | linked list cycle I and II |
| Implicit sequence | `x → f(x)` instead of `node.next` | happy number, find the duplicate |
| Fixed gap | same speed, fast starts k ahead | remove the nth node from the end |

## The core idea: a faster runner laps a slower one

Two runners, one track. On a straight road the fast one reaches the end having covered **twice** the distance, so the slow one is half way: the middle. If the road ends in a loop, both end up circling it, and the fast one gains **exactly one node per step**. A gap that shrinks by one can't jump from 1 to -1: it hits 0, and they meet.

Watch both phases, or build your own list with **Edit input**:

<AlgoViz trace={floydCycle} />

**Why the second walk finds the entry.** Let `F` be the steps from the head to the entry and `a` how far past the entry they met. Fast walked twice slow's `s` steps and stands on the same node, so the extra `s` steps are whole laps. Slow is `a` steps into the loop, so `F + a` is whole laps too: walk `F` more steps from the meeting point and you land on the entry, the moment a pointer from the head arrives.

## Step by step

<Steps>
  <Step title="Find the hidden list">
    What is `next`? `node.next`, the digit-square sum for Happy Number, or `i → nums[i]` for Find the Duplicate.
  </Step>
  <Step title="Pick the loop condition">
    `while (fast && fast.next)` keeps `fast.next.next` safe; Template 1 shows which middle each condition gives.
  </Step>
  <Step title="Move, then compare">
    Both start on the head, so move first and compare after. Compare **nodes** (`slow === fast`), never values.
  </Step>
  <Step title="Decide what the meeting means">
    `fast` hit null: no cycle. A meeting: a cycle, whose entry phase 2 finds.
  </Step>
  <Step title="Check the tiny cases">
    Empty list, one node, two nodes, a node pointing to itself, and a loop covering the whole list (`F = 0`).
  </Step>
</Steps>

## Template 3: cycles in implicit sequences

Floyd's algorithm only needs "the next one". Any function `f` over a finite set gives a sequence `x0, f(x0), f(f(x0)), …` that must repeat, shaped like the letter ρ: a tail into a loop. Replace `node.next` with `f(x)` and the same two phases find the loop's start.

## Complexity

| Variant | Time | Extra space |
|---|---|---|
| Find the middle | O(n) | O(1) |
| Detect a cycle | O(n): slow is caught within its first lap | O(1) |
| Find the cycle's entry | O(n): phase 2 adds F steps | O(1) |
| Implicit sequence | O(tail + cycle length) calls to f | O(1) |
| Visited `Set`, for comparison | O(n) | O(n) |

## JavaScript you'll use

<JsRef to={["linked-list-tree-nodes"]} />

```js
while (fast && fast.next) {       // check fast first: null.next throws
  slow = slow.next;
  fast = fast.next.next;
  if (slow === fast) break;       // === on objects compares identity: the same node
}
const seen = new Set();           // the O(n)-space alternative: seen.has(node)
```

`===` on objects is `true` only for the **same object**: exactly "same node". Comparing `.val` accepts two different nodes holding equal numbers.

<Callout kind="warning">

- Checking only `fast.next` in the loop condition: once `fast` is `null`, `fast.next` throws a TypeError.
- Returning the phase 1 meeting point as the entry: it is somewhere inside the loop, not necessarily its start.
- Starting both pointers on `x0` in an implicit sequence with a plain `while (slow !== fast)`: the loop never runs. Use `do … while`.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="Why does fast move two steps? Would three be faster?">
    Starting together, any speed above 1 catches slow, at the latest once slow's step count is a multiple of the loop length. But only speed 2 makes slow's own distance whole laps, which phase 2 needs: with speed 3 the second walk can miss the entry.
  </FollowUp>
  <FollowUp q="How do you find the length of the cycle?">
    After the meeting, hold one pointer and step the other around until it returns, counting the steps.
  </FollowUp>
  <FollowUp q="Set of visited nodes or Floyd: which would you write first?">
    The `Set`: simpler, also O(n) time, a fine first answer if you name its O(n) memory. Floyd answers the follow-up, "O(1) space?".
  </FollowUp>
  <FollowUp q="How do you find where two linked lists intersect?">
    Walk one pointer from each head; at the end, send each to the **other** list's head. Both travel A + B nodes and arrive at the intersection together, or at null together.
  </FollowUp>
  <FollowUp q="Can you check that a linked list is a palindrome in O(1) space?">
    Find the middle, reverse the second half in place ([in-place list reversal](/dsa/patterns/linked-list-reversal)) and compare the halves node by node: O(n) time.
  </FollowUp>
</FollowUps>
