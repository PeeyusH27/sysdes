<TLDR>
Backtracking builds an answer **one choice at a time**: choose, explore, then **un-choose** and try the next. It is slow by nature, so the craft is skipping dead ends early.
</TLDR>

## When to reach for it

<Callout kind="tip" title="Spot it in the problem statement">

- "Return **all** subsets, combinations, permutations or partitions."
- "Generate **every valid** string, board or arrangement."
- **Place** items under constraints: queens, sudoku digits, a word in a grid.
- **Small limits** like `n <= 10` or a 6 × 6 board: exponential is expected.
- "Does **any** assignment exist?" with no greedy or DP shortcut.

</Callout>

| Variant | Repeats avoided by | Classic problem |
|---|---|---|
| Subsets, combinations | a start index | subsets |
| Permutations | a `used[]` array | permutations |
| Placement | fixed slot order | n-queens |
| Grid search | mark, then restore | word search |

## The core idea: one path, walked forward and back

Picture a maze with a ball of string. At each fork you pick a corridor and unroll the string. At a dead end you wind it back to the fork and try the next corridor. That is backtracking.

Every sequence of choices forms a tree: each edge is a choice, each node a partial answer. You walk it with **one shared `path`**:

1. **Choose**: add an option to `path`.
2. **Explore**: recurse into everything that follows.
3. **Un-choose**: remove it, so `path` is as it was.

Check two things: every answer appears, and each appears once.

## Step by step

<Steps>
  <Step title="Define the partial solution and when it is complete">
    A `path` array. Complete means length k, target hit or row n reached.
  </Step>
  <Step title="List the choices at one step">
    The next number, column or cell: the loop inside the recursive function.
  </Step>
  <Step title="Rule out duplicates by construction">
    Order irrelevant: `start` index. Order matters: `used[]`.
  </Step>
  <Step title="Write choose, explore, un-choose">
    Undo every change right after the recursive call.
  </Step>
  <Step title="Record copies">
    `result.push([...path])`. Pushing `path` itself stores an array that ends up empty.
  </Step>
  <Step title="Prune">
    Ask "can this branch still succeed?" **before** recursing.
  </Step>
</Steps>

## Complexity

Estimate **(nodes in the tree) × (work per node)**.

| Problem | Time | Space |
|---|---|---|
| All subsets of n items | O(n · 2^n) | O(n) |
| All permutations | O(n · n!) | O(n) |
| Word in an m × n grid | O(m · n · 3^L) | O(L) |

## JavaScript you'll use

<JsRef to={["recursion", "arrays", "destructuring-spread"]} />

```js
result.push([...path]);                    // record a COPY of the current path
path.push(x); backtrack(i + 1); path.pop(); // choose, explore, un-choose
const used = new Array(n).fill(false);     // flags for permutations
const word = path.join("");                // character path -> string answer
const board = Array.from({ length: n }, () => Array(n).fill(".")); // n independent rows
```

<Callout kind="warning">

- Forgetting to undo **every** change: `pop()`, `used[i] = false`, the restored cell.
- Recursing with `start + 1` instead of `i + 1`: creates duplicates.
- Pruning with `break` on **unsorted** input.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="The input has duplicates. How do you avoid duplicate answers?">
    Sort, then skip `nums[i]` when it equals `nums[i - 1]` and that value was already tried at this level.
  </FollowUp>
  <FollowUp q="How is backtracking different from DFS and dynamic programming?">
    Backtracking **is** DFS over partial solutions, with an undo. DP applies when paths reach the **same** subproblem. Counting subsets is DP; listing them is backtracking.
  </FollowUp>
  <FollowUp q="How would you search a grid for many words at once?">
    Put the words in a **trie** and run one search per cell, following trie children.
  </FollowUp>
</FollowUps>
