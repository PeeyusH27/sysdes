<TLDR>
Greedy takes whatever looks best **right now** and never takes it back: usually a sort plus one pass. It is correct only when you can **prove** the choice is safe. A small counterexample means DP.
</TLDR>

## The core idea: a choice you never regret

Picture handing out cookies to children. Each child wants a cookie of at least some size. Give the **smallest cookie that works** to the **least greedy** child. A bigger cookie can't do better here, and it may be needed later.

<AlgoViz trace={assignCookies} />

Greedy code is easy. The hard part is knowing the choice can't hurt. Name the proof in an interview:

- **Exchange argument**: take any best answer. If it skips your choice, swap yours in. It is still valid and no worse.
- **Stays ahead**: show greedy is never behind. In scheduling, greedy's k-th interval ends no later than any other schedule's k-th.

No proof? Hunt for a counterexample, then use [dynamic programming](/dsa/patterns/dp-1d).

## Template 3: one pass with a running best

Many greedy solutions never sort: one scan, one number that sums up the past.

```js
let reach = 0;                                   // Jump Game: furthest index reachable so far
for (let i = 0; i < nums.length; i++) {
  if (i > reach) return false;                   // a gap nothing can cross
  reach = Math.max(reach, i + nums[i]);
}
return true;
```

- <ProblemLink slug="best-time-to-buy-and-sell-stock" />: the cheapest price so far.
- <ProblemLink slug="jump-game" />: the furthest reachable index.
- <ProblemLink slug="jump-game-ii" />: count frontier extensions.
- <ProblemLink slug="gas-station" />: running dry at station `i` rules out every start before it.
- <ProblemLink slug="partition-labels" />: cut when the scan reaches the furthest last occurrence.

Need both directions? Make **two passes**, as in <ProblemLink slug="candy" />.

## When greedy fails

"Make change with the fewest coins: take the largest coin that fits." Coins `4, 3, 1` and amount 6: greedy pays 4 + 1 + 1. But 3 + 3 needs only two. The 4 felt like progress, then trapped you.

<AlgoViz trace={greedyCoins} />

The fix: stop committing. Dynamic programming finds the best answer for **every** smaller amount, trying each coin as the last one.

## Complexity

| Variant | Time | Space |
|---|---|---|
| Sort, then one pass | O(n log n) | O(1) to O(n) |
| One pass, running best | O(n) | O(1) |
| Coin change by DP | O(amount × coins) | O(amount) |

## JavaScript you'll use

<JsRef to={["sorting", "numbers-math"]} />

```js
const sorted = [...items].sort((a, b) => a - b);   // copy first if the caller's order matters
intervals.sort((a, b) => a[1] - b[1]);             // by end time
let best = -Infinity, cheapest = Infinity;         // sentinels: any real value beats them
best = Math.max(best, price - cheapest);           // Infinity arithmetic is safe: 5 - Infinity is -Infinity
const total = nums.reduce((sum, x) => sum + x, 0); // feasibility totals (gas station)
```

`sort` works **in place**: copy with `[...arr]` if the order matters later.

<Callout kind="warning">

- Ties: `start > lastEnd` instead of `>=` rejects intervals that only touch.
- Overwriting instead of taking a max in a second pass.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="How do you convince an interviewer your greedy is correct?">
    Name the argument (exchange, or stays ahead) and walk their example through it. Offer the DP if you can't argue it.
  </FollowUp>
  <FollowUp q="For which coin systems does greedy change-making work?">
    "Canonical" ones like 1, 5, 10, 25. Coins 1, 3, 4 fail at 6. With arbitrary coins, use DP.
  </FollowUp>
  <FollowUp q="Greedy or dynamic programming: how do you decide quickly?">
    Ask whether an early choice can be regretted. Test a few tiny inputs against a brute force.
  </FollowUp>
</FollowUps>
