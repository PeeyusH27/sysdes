<TLDR>
Dynamic programming is recursion that **never solves the same subproblem twice**. Define `dp[i]`, build it from smaller indices and fill in dependency order: an exponential brute force becomes O(states × choices), often with O(1) extra space.
</TLDR>

## When to reach for it

<Callout kind="tip" title="Spot it in the problem statement">

- It asks for **the number of ways**, or the **minimum or maximum** cost over a series of choices.
- It asks **"is it possible?"** when choices combine in many orders.
- Your brute-force recursion keeps calling itself with the **same arguments**.
- n (or an amount) is up to about 10^4, so O(n²) or O(n × amount) fits.

</Callout>

Listing every solution is [Backtracking](/dsa/patterns/backtracking). One provably safe local rule is [Greedy](/dsa/patterns/greedy). DP is for when greedy has a counterexample.

| Variant | `dp[i]` means | Classic problems |
|---|---|---|
| Fixed look-back | the answer for step `i` (reads `i - 1`, `i - 2`) | Climbing Stairs, House Robber, Decode Ways |
| Ending exactly at `i` | the best answer whose last element is `nums[i]` | Maximum Subarray, Longest Increasing Subsequence |
| Over an amount | the answer for a total of `a` | Coin Change, Perfect Squares, Combination Sum IV |
| Prefix with a cut | the answer for `s.slice(0, i)` | Word Break, Palindrome Partitioning II |

## The core idea: solve each subproblem once

Plain recursion asks the same question again and again. DP asks each one once.

Take **Min Cost Climbing Stairs**: `cost[i]` is what you pay to leave step `i`, each move climbs one or two steps, you start free on step 0 or 1, and the top is step `n`. Think about the **last move**: you reached step `i` from `i - 1` or from `i - 2`.

```js
best(i) = Math.min(best(i - 1) + cost[i - 1], best(i - 2) + cost[i - 2]);   // best(0) = best(1) = 0
```

Correct, and exponential: every call makes two more. But there are only `n + 1` different questions, so a **memo** (a Map from `i` to its answer) turns every repeat into an O(1) lookup. Compare both presets in the walkthrough, then try your own costs with Edit input:

DP needs two properties:

- **Overlapping subproblems**: the same smaller question keeps coming up. Merge sort's halves never repeat, so a memo saves nothing there.
- **Optimal substructure**: the best answer for `i` is built from best answers for smaller indices. Longest simple path fails: the best continuation depends on which nodes you already used.

## Step by step: the DP recipe

Six questions, in order, turn a brute force into a DP.

<Steps>
  <Step title="Define the state in words">
    "`dp[i]` = the cheapest total cost to stand on step `i`." Say what `i` is (index, length, amount) and whether element `i` must be used ("ending at `i`") or may be skipped ("the first `i` items"). Most wrong DPs start with a vague sentence here.
  </Step>
  <Step title="Write the recurrence from the last decision">
    The last move came from `i - 1` or `i - 2`; the last coin was one of the coins. Combine with `min`, `max`, `+` (counting) or `||` (feasibility).
  </Step>
  <Step title="Pin down the base cases">
    Here `dp[0] = dp[1] = 0`. In counting, the empty choice is **one** way (`dp[0] = 1`); in minimums, unreachable states start at `Infinity`.
  </Step>
  <Step title="Choose the evaluation order">
    Every cell after the cells it reads: smaller indices mean loop `i` upward. Top-down with a memo finds the order for you, at the price of a call stack.
  </Step>
  <Step title="Read the answer cell">
    `dp[n]` (the top, one past the last step), `dp[amount]`, or the **best over all cells** for "ending at `i`" states. `Infinity` usually becomes `-1` on the way out.
  </Step>
  <Step title="Optimise the space">
    If `dp[i]` reads only the last one or two cells, keep two variables: O(n) space becomes O(1). If it reads arbitrary earlier cells (LIS, Word Break), keep the array.
  </Step>
</Steps>

## Template 3: ending at i, looking back at every earlier j

For "best subsequence" problems, let `dp[i]` be the best answer **whose last element is `nums[i]`**: scan every earlier `j` that may come before `i` and extend the best. That's O(n²), and the answer is the best cell, because the winner can end anywhere.

## Complexity

Time is **states × work per state**; space is the table (or kept variables) plus any call stack.

| Form or variant | Time | Extra space |
|---|---|---|
| Plain recursion (two branches) | O(2^n) | O(n) call stack |
| Memoized recursion | O(n) | O(n) memo + O(n) call stack |
| Bottom-up table, or rolling variables | O(n) | O(n), or O(1) |
| Over an amount `A` with `k` choices | O(A × k) | O(A) |
| Ending at `i`, every `j` before it | O(n²) | O(n) |

## JavaScript you'll use

<JsRef to={["recursion", "arrays", "map-set"]} />

```js
const dp = new Array(n + 1).fill(0);           // one cell per state, n + 1 when the top is index n
const best = new Array(amount + 1).fill(Infinity);
best[0] = 0;                                   // Infinity = "can't be made", min() ignores it
const memo = new Map();                        // if (memo.has(key)) return memo.get(key);
[twoBack, oneBack] = [oneBack, current];       // roll two variables forward
return best[amount] === Infinity ? -1 : best[amount];
```

The memo trap: `if (memo.get(i))` treats a cached `0` as missing and brings the blow-up back, so test `memo.has(i)`. The call stack holds roughly 10,000 frames, so memoized recursion on `n = 10^5` throws `RangeError: Maximum call stack size exceeded`: go bottom-up.

<Callout kind="warning">

- Sizing the table `n` instead of `n + 1`, then reading `dp[n - 1]` instead of `dp[n]`.
- `Math.max(...dp)` on 10^5+ cells can overflow the stack: track the best in the loop.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="Top-down or bottom-up: which should I write in an interview?">
    Top-down when the recurrence is the hard part: it reads like the brute force plus a two-line memo, and wins when few states are reachable. Bottom-up for large inputs (no stack limit) or O(1) space, which needs an explicit order.
  </FollowUp>
  <FollowUp q="How do you know it's DP and not greedy?">
    Try to break greedy on a small case: coins 1, 3 and 4 for amount 6 give 4 + 1 + 1 greedily, but 3 + 3 uses two coins. A counterexample means DP; an exchange argument that greedy never loses means greedy is enough.
  </FollowUp>
  <FollowUp q="The interviewer wants the actual choices, not just the optimal value. What changes?">
    Keep the full table and walk from the answer cell to a base case, asking which option produced each cell (did `dp[i]` come from `i - 1` or `i - 2`?). O(n) extra time, and the O(n) table can't be dropped.
  </FollowUp>
  <FollowUp q="Can Longest Increasing Subsequence beat O(n²)?">
    Yes, O(n log n). Keep `tails[k]` = the smallest last value of an increasing subsequence of length `k + 1`; binary-search each number's first tail at least as large and overwrite it (or append). The length of `tails` is the answer; the subsequence needs predecessor links.
  </FollowUp>
  <FollowUp q="How do you count ways modulo 10^9 + 7 in JavaScript?">
    `% MOD` after every addition keeps values below 2 × 10^9 + 14, far under 2^53, so they stay exact. A product of two such values can exceed 2^53: use `BigInt` or split the multiplication.
  </FollowUp>
</FollowUps>
