<TLDR>
Dynamic programming is recursion that **never solves the same question twice**. Write each answer down once, build it from smaller answers, and a slow brute force becomes a quick loop.
</TLDR>

## When to reach for it

<Callout kind="tip" title="Spot it in the problem statement">

- It asks for **the number of ways**, or the **minimum or maximum** over a series of choices.
- It asks **"is it possible?"** when choices combine in many orders.
- Your brute-force recursion keeps calling itself with the **same arguments**.
- n (or an amount) is up to about 10^4.

</Callout>

Listing every solution is [Backtracking](/dsa/patterns/backtracking). DP is for when [Greedy](/dsa/patterns/greedy) has a counterexample.

| Variant | `dp[i]` means | Classic problem |
|---|---|---|
| Fixed look-back | answer for step `i` | Climbing Stairs |
| Ending at `i` | best answer ending at `nums[i]` | Longest Increasing Subsequence |
| Over an amount | answer for total `a` | Coin Change |
| Prefix with a cut | answer for `s.slice(0, i)` | Word Break |

## The core idea: solve each subproblem once

Picture a staircase with a toll on each step. You climb one or two steps at a time and want the cheapest way to the top. Ask only about the **last move**: you reached step `i` from `i - 1` or from `i - 2`. So the cheapest way to `i` is the cheaper of those two.

```js
best(i) = Math.min(best(i - 1) + cost[i - 1], best(i - 2) + cost[i - 2]);   // best(0) = best(1) = 0
```

Correct, but slow: every call makes two more, repeating the same questions. There are only `n + 1` different ones. So write each answer on a **sticky note** (a **memo**) and look it up next time. Compare both presets, then try your own costs with Edit input:

<AlgoViz trace={recursionTree} />

Two things make a problem fit:

- **Repeated questions**: the same small question keeps coming back.
- **Built from smaller answers**: the best answer for `i` comes from best answers for smaller indices.

## Step by step: the DP recipe

Six questions, in order, turn a brute force into a DP.

<Steps>
  <Step title="Define the state in words">
    "`dp[i]` = the cheapest cost to stand on step `i`." Vague here means wrong later.
  </Step>
  <Step title="Write the recurrence from the last decision">
    The last move came from `i - 1` or `i - 2`. Combine with `min`, `max`, `+` (counting) or `||` (feasibility).
  </Step>
  <Step title="Pin down the base cases">
    Here `dp[0] = dp[1] = 0`. When counting, doing nothing is **one** way (`dp[0] = 1`).
  </Step>
  <Step title="Choose the evaluation order">
    Fill each cell after the cells it reads: loop `i` upward.
  </Step>
  <Step title="Read the answer cell">
    `dp[n]`, `dp[amount]`, or the **best over all cells**.
  </Step>
  <Step title="Optimise the space">
    If `dp[i]` reads only the last one or two cells, keep two variables.
  </Step>
</Steps>

## Complexity

Time is **states × work per state**.

| Form | Time | Space |
|---|---|---|
| Plain recursion | O(2^n) | O(n) |
| Memo or table | O(n) | O(n) |
| Rolling variables | O(n) | O(1) |
| Ending at `i`, every `j` | O(n²) | O(n) |

## JavaScript you'll use

<JsRef to={["recursion", "arrays", "map-set"]} />

```js
const dp = new Array(n + 1).fill(0);           // one cell per state, n + 1 when the top is index n
const best = new Array(amount + 1).fill(Infinity);
best[0] = 0;                                   // Infinity = "can't be made", min() ignores it
const memo = new Map();                        // if (memo.has(key)) return memo.get(key);
[twoBack, oneBack] = [oneBack, current];       // roll two variables forward
return best[amount] === Infinity ? -1 : best[amount];
```

The memo trap: `if (memo.get(i))` treats a cached `0` as missing, so test `memo.has(i)`. Memoized recursion on `n = 10^5` overflows the stack: go bottom-up.

<Callout kind="warning">

- Sizing the table `n` instead of `n + 1`.
- `Math.max(...dp)` on 10^5+ cells overflows the stack.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="Top-down or bottom-up: which should I write in an interview?">
    Top-down when the recurrence is the hard part: it is the brute force plus a two-line memo. Bottom-up for large inputs or O(1) space.
  </FollowUp>
  <FollowUp q="How do you know it's DP and not greedy?">
    Try to break greedy on a small case: coins 1, 3, 4 for amount 6. Greedy gives 4 + 1 + 1, but 3 + 3 is better. A counterexample means DP.
  </FollowUp>
  <FollowUp q="The interviewer wants the actual choices, not just the value. What changes?">
    Keep the full table. Walk back from the answer cell, asking which option produced each cell.
  </FollowUp>
</FollowUps>
