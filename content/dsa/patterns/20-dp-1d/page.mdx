<TLDR>
Dynamic programming is recursion that **never solves the same subproblem twice**. Say in words what `dp[i]` means, write how it is built from smaller indices, and fill a table in an order where everything a cell needs is already there. An exponential brute force becomes O(number of states × choices per state), and often O(1) extra space once you notice each cell only reads the last one or two.
</TLDR>

## When to reach for it

<Callout kind="tip" title="Spot it in the problem statement">

- It asks for **the number of ways** to do something (a count, not the list itself).
- It asks for the **minimum or maximum** cost, length, sum or profit over a series of choices.
- It asks **"is it possible?"** when choices can be combined in many orders.
- Your brute-force recursion calls itself with the **same arguments again and again** (overlapping subproblems), and the best answer for a big input is built from best answers for smaller ones (optimal substructure).
- The input is small enough for O(n²) or O(n × amount): n up to about 10^4, an amount up to about 10^4.

</Callout>

If the problem wants **every** solution listed, that is [Backtracking](/dsa/patterns/backtracking): DP counts or optimises, it doesn't enumerate. If one local rule is provably always right, [Greedy](/dsa/patterns/greedy) is simpler. DP is what you use when greedy has a counterexample.

| Variant | `dp[i]` means | Each cell reads | Classic problems |
|---|---|---|---|
| Fixed look-back | the answer for step `i`, or for the first `i` items | `dp[i - 1]`, `dp[i - 2]` | Climbing Stairs, House Robber, Min Cost Climbing Stairs, Decode Ways |
| Ending exactly at `i` | the best answer whose last element is `nums[i]` | `dp[i - 1]` (Kadane) or every `dp[j]` with `j < i` | Maximum Subarray, Longest Increasing Subsequence |
| Over an amount | the answer for a total of `a` | `dp[a - c]` for every choice `c` | Coin Change, Perfect Squares, Combination Sum IV |
| Prefix with a cut | the answer for the prefix `s.slice(0, i)` | every `dp[j]`, `j < i`, where the piece `s.slice(j, i)` passes a check | Word Break, Palindrome Partitioning II |

## The core idea: solve each subproblem once

One problem runs through this whole lesson. **Min Cost Climbing Stairs**: `cost[i]` is what you pay to leave step `i`; each move climbs one or two steps; you may start on step 0 or step 1 for free; the top is step `n`, one past the last step. What is the cheapest way to the top?

Think about the **last move**. You reach step `i` either from step `i - 1` (paying `cost[i - 1]`) or from step `i - 2` (paying `cost[i - 2]`). So if `best(i)` is the cheapest cost to stand on step `i`:

```js
best(i) = Math.min(best(i - 1) + cost[i - 1], best(i - 2) + cost[i - 2]);   // best(0) = best(1) = 0
```

That recursion is correct, and exponential: every call makes two more. But `best` only depends on `i`, so there are just `n + 1` different questions. Plain recursion asks most of them many times; a **memo** (a Map from `i` to its answer) makes every repeat an O(1) lookup. Step through both presets and compare the trees:

Two properties make this work, and you should check both before writing any DP:

- **Overlapping subproblems.** The same smaller question comes up again and again. Without overlap, a memo saves nothing (merge sort's halves never repeat).
- **Optimal substructure.** The best answer for `i` is built from the best answers for smaller indices, whatever path led there. Longest simple path in a graph fails this: the best continuation depends on which nodes you already used, so `i` alone isn't a complete state.

## Step by step: the DP recipe

<Steps>
  <Step title="Define the state in words">
    Write one sentence: "`dp[i]` = the cheapest total cost to stand on step `i`." Be exact about what `i` is (an index, a length, an amount), whether the element at `i` must be used ("ending at `i`") or may be skipped ("using the first `i` items"), and what the number is (count, min, max, true/false). Most wrong DPs are a vague sentence here.
  </Step>
  <Step title="Write the recurrence from the last decision">
    Ask "what was the last choice?" and express `dp[i]` through smaller states: the last move came from `i - 1` or `i - 2`, the last coin was one of the coins, the last word ended at `i`. Combine with `min`, `max`, `+` (counting) or `||` (feasibility).
  </Step>
  <Step title="Pin down the base cases">
    The states the recurrence can't build: `dp[0] = dp[1] = 0` here. For counting, the empty choice usually counts as **one** way (`dp[0] = 1`). For minimums, unreachable states start at `Infinity`. Check them against the tiniest input by hand.
  </Step>
  <Step title="Choose the evaluation order">
    Every cell must be computed after the cells it reads. If `dp[i]` reads smaller indices, loop `i` upward. Top-down recursion with a memo finds this order for you, at the price of a call stack.
  </Step>
  <Step title="Read the answer cell">
    Say which cell answers the question: `dp[n]` (the top, one past the last step), `dp[amount]`, or the **best over all cells** for "ending at `i`" states. Convert sentinels on the way out: `Infinity` usually becomes `-1`.
  </Step>
  <Step title="Optimise the space">
    If `dp[i]` only reads the previous one or two cells, keep just those in variables: O(n) space becomes O(1). If it reads arbitrary earlier cells (LIS, Word Break, amounts), keep the array.
  </Step>
</Steps>

## Template 2: DP over an amount

When the input is a **target number** and a set of pieces that can be reused, index the table by the amount. `dp[a]` tries every possible **last piece** and reads the cell for what is left. Cells that can't be made stay at `Infinity`. The canonical example is the fewest perfect squares that add up to `n`:

## Template 3: ending at i, looking back at every earlier j

Some answers have no fixed look-back. For "the best subsequence" problems, define `dp[i]` as the best answer **whose last element is `nums[i]`**. Then `dp[i]` scans every earlier `j` that may come right before `i` and extends the best of them. It costs O(n²), and the answer is the best cell, because the winning subsequence may end anywhere.

The same state solves <ProblemLink slug="longest-increasing-subsequence" /> (add 1 instead of `nums[i]`). <ProblemLink slug="maximum-subarray" /> is the contiguous special case: the only `j` that can come before `i` is `i - 1`, so `dp[i] = Math.max(nums[i], dp[i - 1] + nums[i])` and the look-back shrinks to one variable (Kadane's algorithm). <ProblemLink slug="word-break" /> uses a prefix state instead: `dp[i]` is true when some cut `j` has `dp[j]` true and `s.slice(j, i)` is a word.

## Complexity

Time is always **number of states × work per state**; space is the table (or the variables you kept) plus any call stack.

| Form or variant | Time | Extra space |
|---|---|---|
| Plain recursion (two branches) | O(2^n) | O(n) call stack |
| Memoized recursion | O(n) | O(n) memo + O(n) call stack |
| Bottom-up table | O(n) | O(n) |
| Rolling variables | O(n) | O(1) |
| Over an amount `A` with `k` choices | O(A × k) | O(A) |
| Ending at `i`, every `j` before it | O(n²) | O(n) |

## JavaScript you'll use

<JsRef to={["recursion", "arrays", "map-set"]} />

```js
const dp = new Array(n + 1).fill(0);           // one cell per state, n + 1 when the top is index n
const best = new Array(amount + 1).fill(Infinity);
best[0] = 0;                                   // Infinity = "can't be made", min() ignores it
const memo = new Map();                        // if (memo.has(key)) return memo.get(key);
[twoBack, oneBack] = [oneBack, current];       // roll two variables forward
return best[amount] === Infinity ? -1 : best[amount];
```

The memo trap: `if (memo.get(i))` treats a cached `0` (or `false`) as missing, so those subproblems are recomputed and the exponential blow-up comes back. Always test with `memo.has(i)`. And JavaScript's call stack holds roughly 10,000 frames, so a memoized recursion on `n = 10^5` throws `RangeError: Maximum call stack size exceeded`: switch to the bottom-up loop.

<Callout kind="warning">

- Sizing the table `n` instead of `n + 1`, then reading the answer from the wrong cell (`dp[n - 1]` instead of `dp[n]`).
- Wrong base case: the empty amount has **one** way to be made in counting problems and costs **0** in minimum problems.
- Filling in an order where a cell reads a neighbour that isn't computed yet: it silently uses the initial `0` or `Infinity`.
- Returning `Infinity` (or `-Infinity`) to the caller instead of the `-1` or `0` the problem asks for.
- Checking `if (memo[i])` instead of `memo.has(i)` or `memo[i] !== undefined`.
- `Math.max(...dp)` on a very large array: spreading 10^5+ arguments can overflow the stack; track the best in the loop instead.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="Top-down or bottom-up: which should I write in an interview?">
    Start top-down when the recurrence is the hard part: it reads exactly like the brute force, and the memo is two lines. Switch to bottom-up when the input is large (no stack limit), when the interviewer asks for O(1) space (you need the explicit order to roll variables), or when the state space is dense anyway. Top-down wins when only a few states are actually reachable. Say this trade-off out loud; it is a common follow-up.
  </FollowUp>
  <FollowUp q="How do you know it's DP and not greedy?">
    Try to break the greedy rule with a small example. For Coin Change with coins 1, 3 and 4 and amount 6, "take the biggest coin" gives 4 + 1 + 1 (three coins) but 3 + 3 uses two. A counterexample means a local choice can block a better global one, so you must consider every last choice: DP. If you can prove an exchange argument (swapping any choice for the greedy one never hurts), greedy is enough.
  </FollowUp>
  <FollowUp q="The interviewer wants the actual choices, not just the optimal value. What changes?">
    Keep the full table (no rolling variables) and, for each cell, either record which option won or recompute it on the way back. Then walk from the answer cell to a base case: for the stairs, at step `i` ask whether `dp[i]` came from `i - 1` or `i - 2`. The walk costs O(n) extra time; the space is the O(n) table you could otherwise have dropped.
  </FollowUp>
  <FollowUp q="Can Longest Increasing Subsequence beat O(n²)?">
    Yes, O(n log n). Keep `tails[k]` = the smallest possible last value of an increasing subsequence of length `k + 1`. For each number, binary-search the first tail that is at least as large and overwrite it (or append when none is). `tails` stays sorted, and its length is the answer. It gives the length, not the subsequence itself, unless you also track predecessors.
  </FollowUp>
  <FollowUp q="How do you count ways modulo 10^9 + 7 in JavaScript?">
    Apply `% MOD` after every addition so values stay below 2 × 10^9 + 14, far under 2^53, and remain exact. For products of two values below MOD, the product can exceed 2^53, so use `BigInt` or split the multiplication. Forgetting the modulo makes numbers silently lose precision long before they look wrong.
  </FollowUp>
</FollowUps>
