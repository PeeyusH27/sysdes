<TLDR>
Breadth-first search reads a tree **level by level** with a first-in, first-out queue. **Snapshot the queue size** when a level starts and you know where it ends. Shallow nodes come first, so BFS can **stop at the first match**. O(n) time.
</TLDR>

## The core idea: a queue keeps the levels in order

<Doodle name="queue" size={150} caption />

Drop a stone in a pond: the ripples spread one ring at a time. A **queue** does the same to a tree. Take a node out of the front, put its children at the back. They wait **behind** every node of the current level, so nodes come out in depth order.

One rule follows:

> When a level starts, the queue holds exactly that level, and nothing else.

So read `size` then, and take out exactly `size` nodes. Whatever they add is the next level. Watch the shaded band (this level) and the new arrivals (the next):

## Step by step

<Steps>
  <Step title="Handle the empty tree">
    Return `[]` or `0` when `root` is `null`.
  </Step>
  <Step title="Seed the queue">
    Root in an array, plus a `head` index.
  </Step>
  <Step title="Snapshot the level size">
    `size = queue.length - head`.
  </Step>
  <Step title="Process the level">
    Dequeue `size` nodes, then enqueue their children.
  </Step>
  <Step title="Record or stop">
    Push the level's answer, or return at the first match.
  </Step>
</Steps>

## Complexity

| Variant | Time | Extra space |
|---|---|---|
| Level-size BFS | O(n): each node enqueued and dequeued once | O(w): the widest level, up to about n / 2 |
| Early exit (first match) | O(n) worst case, often far less | O(w) for the levels it reaches |
| BFS with `shift()` | O(n²) worst case on large queues | O(w) |
| DFS passing the depth down | O(n) | O(h) for the recursion |

## JavaScript you'll use

<JsRef to={["stack-queue-deque", "linked-list-tree-nodes", "arrays"]} />

```js
const queue = root ? [root] : [];       // a queue: push at the back, read at head
let head = 0;
const size = queue.length - head;       // snapshot: the nodes of the current level
const node = queue[head++];             // O(1) dequeue, nothing moves
if (node.left) queue.push(node.left);   // never enqueue null children
level[size - 1 - i] = node.val;         // fill from the back for a right-to-left level
const avg = sum / size;                 // / is always floating-point division in JS
```

<Callout kind="warning">

- Looping on the live `queue.length` inside a level.
- Enqueuing `null` children, then reading `.val`.
- For zigzag, reversing the order children are **enqueued**.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="BFS or DFS for a level-based question?">
    Both work. BFS holds one level and can stop early; DFS holds one path, which is n for a skewed tree.
  </FollowUp>
  <FollowUp q="How do you return the levels bottom-up?">
    Run the normal BFS and reverse the list of levels once at the end.
  </FollowUp>
  <FollowUp q="How do you link every node to its right neighbour on the same level?">
    In the level-size loop, link each node to the next one unless it is last in its level.
  </FollowUp>
  <FollowUp q="How would you find the maximum width of a level, counting the gaps?">
    Number positions like a heap (children of p at 2p + 1 and 2p + 2). Width is last minus first plus one.
  </FollowUp>
</FollowUps>
