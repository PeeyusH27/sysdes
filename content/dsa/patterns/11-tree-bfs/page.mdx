<TLDR>
Breadth-first search reads a tree **level by level** with a first-in, first-out queue. **Snapshot the queue size** when a level starts and you know exactly where it ends; and because shallow nodes come first, BFS can **stop at the first match**. O(n) time, O(w) space for the widest level.
</TLDR>

## When to reach for it

<Callout kind="tip" title="Spot it in the problem statement">

- The answer is **per level** or per row: averages, maximums, the values of each level.
- What is visible **from one side**: the first or last node on every level.
- The **nearest** or shallowest something: minimum depth, the closest leaf.
- Output ordered **top to bottom, left to right**, or neighbours on the **same level** linked together.

</Callout>

## The core idea: a queue keeps the levels in order

A queue hands nodes out in the order they went in. Take a node out, put its children in at the back: they join **behind** every node of the current level still waiting. So nodes come out in depth order, left to right within a level, and one invariant follows:

> When a level starts, the queue holds exactly the nodes of that level, and nothing else.

So read `size` then and dequeue exactly `size` nodes; everything they add is the next level. Watch the shaded band (this level) and the new arrivals (the next):

## Step by step

<Steps>
  <Step title="Handle the empty tree">
    Return `[]` or `0` when `root` is `null`, never `[[]]`.
  </Step>
  <Step title="Seed the queue">
    Put the root in an array and keep a `head` index: `queue[head++]` is an O(1) dequeue, `shift()` is not.
  </Step>
  <Step title="Snapshot the level size">
    At the top of the outer loop, `size = queue.length - head`: exactly this level's nodes.
  </Step>
  <Step title="Process the level">
    Dequeue `size` nodes, do the per-level work, and enqueue each node's left child, then its right.
  </Step>
  <Step title="Record or stop">
    Push the level's answer after the inner loop. For "nearest" questions, return at the first match: nothing later is shallower.
  </Step>
</Steps>

## Template 2: stop at the first match

DFS must explore the whole tree to be sure of the shallowest leaf: one at depth 2 on the right only shows up after the entire left side. BFS meets every node at depth d before any at depth d + 1, so **the first match it dequeues is a shallowest one**.

## Template 3: a queue that never shifts

`shift()` moves every remaining element down a slot, so on large queues BFS can turn O(n²). On Node, draining a 50,000-item array with `shift()` takes around 100 ms, and doubling the size roughly quadruples that; a head index takes a couple of milliseconds. Three fixes:

- **Head index**: `queue[head++]`. Fine for one BFS over a tree.
- **Swap arrays per level**: build `next` while walking `level`.
- **A small Queue class** that occasionally slices off the used prefix, for long-running queues.

## Complexity

| Variant | Time | Extra space |
|---|---|---|
| Level-size BFS | O(n): each node enqueued and dequeued once | O(w): the widest level, up to about n / 2 |
| Early exit (first match) | O(n) worst case, often far less | O(w) for the levels it reaches |
| BFS with `shift()` | O(n²) worst case on large queues | O(w) |
| DFS passing the depth down | O(n) | O(h) for the recursion |

## JavaScript you'll use

<JsRef to={["stack-queue-deque", "linked-list-tree-nodes", "arrays"]} />

```js
const queue = root ? [root] : [];       // a queue: push at the back, read at head
let head = 0;
const size = queue.length - head;       // snapshot: the nodes of the current level
const node = queue[head++];             // O(1) dequeue, nothing moves
if (node.left) queue.push(node.left);   // never enqueue null children
level[size - 1 - i] = node.val;         // fill from the back for a right-to-left level
const avg = sum / size;                 // / is always floating-point division in JS
```

<Callout kind="warning">

- Looping on the live `queue.length` inside a level instead of the snapshot: it grows as children join, and the levels run together.
- Enqueuing `null` children, then reading `.val` from them.
- For zigzag, reversing the order children are **enqueued**: that scrambles the levels below.

</Callout>

## Interview questions

<FollowUps>
  <FollowUp q="BFS or DFS for a level-based question?">
    Both work (DFS passes the depth down into `levels[depth]`). BFS holds one level, about n / 2 for a complete tree, and can stop early; DFS holds one path, n for a skewed tree.
  </FollowUp>
  <FollowUp q="How do you return the levels bottom-up?">
    Run the normal BFS and reverse the list of levels once at the end, O(n), rather than calling `unshift` per level.
  </FollowUp>
  <FollowUp q="How do you link every node to its right neighbour on the same level?">
    In the level-size loop, link each node to the next unless it is last in its level. For O(1) space, walk each level through the next pointers already built on the level above.
  </FollowUp>
  <FollowUp q="How would you find the maximum width of a level, counting the gaps between nodes?">
    Number positions like a heap (children of p at 2p + 1 and 2p + 2): width is last minus first plus one. Positions pass 2^53 on deep skewed trees, so subtract each level's first position as you go.
  </FollowUp>
</FollowUps>
