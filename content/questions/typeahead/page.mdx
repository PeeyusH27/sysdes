## Clarifying questions

- **Where do suggestions come from?** A remote API, or a small local list you filter on every key.
- **How many, and what shape?** About 8 plain strings, or rich items.
- **Search box or form field?** A search box runs the typed text. A form field must pick an option.
- **Keyboard, screen readers, mobile?** Always yes.

### Architecture

Play **Typing**, **Arrow keys and Enter** and **Click an option** in the component tree.

<FlowDiagram spec={componentTree} />

- `Typeahead` owns the UI: open, active option.
- `useTypeahead` owns the data: query, timer, abort, cache.
- `fetchSuggestions(q, signal)` is a prop, so any backend plugs in.

### Data model

```js
// Data state, in the hook
{ query: 'rea', status: 'idle' | 'loading' | 'success' | 'error', items: [{ id, label }] }

// UI state, in the component
{ open: true, active: -1 }          // -1 = no option highlighted yet

// Client cache: Map<query, { items, at }>, capped at 100 entries, 60 s TTL.
// Map keeps insertion order, so delete + set on access makes the first key the least recently used.
```

### Interface

```jsx
<Typeahead fetchSuggestions={(q, signal) => api.suggest(q, signal)} onSelect={item => runSearch(item.label)} label="Search" />

useTypeahead(fetchSuggestions, { delay: 250, minChars: 2, ttlMs: 60_000, maxEntries: 100 })
// → { query, setQuery, status, items }
```

```http
GET /api/suggest?q=rea&limit=8

200 OK
Cache-Control: public, max-age=300, stale-while-revalidate=3600

{ "q": "rea", "items": [{ "id": "rea:0", "label": "react" }, { "id": "rea:1", "label": "react native" }] }
```

### Optimizations

- **Fewer requests:** a 2-character minimum and a 250 ms debounce.
- **Fast:** cancel old requests, and keep recent answers for backspace.
- **Safe:** show matches with `<mark>`, never HTML strings.

Do the sum before you pick a backend:

| Data | Load | Use |
|---|---|---|
| 5,000 countries | none | Filter in memory |
| 100,000 products | about 50 requests/s | `LIKE 'rea%'` on an index |
| 100M past searches | thousands/s | Trie, top 8 per node, behind a CDN |

A short prefix like "a" matches millions of rows. Ranking them on every key is what breaks `LIKE`.

## Step-by-step answer

<Steps>
  <Step title="Clarify the scope">
    Then state the plan: a hook, a combobox, a prefix index.
  </Step>
  <Step title="Debounce the input">
    Wait about 250 ms after the last key and skip queries under 2 characters. A fast "react" sends 1 request, not 5. Without it, 10,000 people typing five keys a second can send 50,000 requests a second.
  </Step>
  <Step title="Fix the race">
    Pause twice and the older request may answer last. Cancel it in the effect cleanup, and check the signal too, since some servers ignore cancels:

```js
const items = await load(q, ctrl.signal);
if (ctrl.signal.aborted) return;                   // a newer query took over
// …
return () => { clearTimeout(timer); ctrl.abort(); };   // cleanup: cancel the wait and the request
```
  </Step>
  <Step title="Cache results">
    A Map of query to `{ items, at }`. Drop the oldest past 100 entries and ignore entries older than 60 s. Check it **before** the timer starts. More in the [caching lesson](/learn/caching).
  </Step>
  <Step title="Render an accessible combobox">
    The input is the `combobox`, the list is a `listbox`, each row an `option`. Arrows move, Enter selects, Escape closes, and focus stays in the input. `preventDefault` on an option's `mousedown` stops the blur that would close the list early.
  </Step>
  <Step title="Highlight safely">
    Split the label on the escaped query and wrap the matches in `<mark>`. React escapes all text, so a label like `<img onerror=…>` stays text.

```js
'React Native'.split(/(re)/gi)    // ['', 'Re', 'act Native']: matches land at odd indexes
```
  </Step>
  <Step title="Cover the states">
    **Loading:** keep the old items; show a spinner after about 300 ms. **Empty:** "No suggestions". **Error:** stay quiet; typing still works.
  </Step>
  <Step title="Design the backend">
    A trie built from query logs, where every node holds its top 8 completions. Lookup costs O(prefix length). Rebuild offline and swap. A CDN absorbs hot prefixes. For fuzzy matching, use a search engine.
  </Step>
</Steps>

<Callout kind="interview">
"Debounce cuts how many requests I send, not their order. So each keystroke aborts the last request, and I ignore any result whose signal was aborted."
</Callout>

## Failure modes

| What breaks | Effect | Mitigation |
|---|---|---|
| Answers arrive out of order | An old query's results flash | Abort; ignore aborted results |
| API down | No suggestions | Quiet error; typing still works |
| Slow network | Feels laggy | Keep old items; spinner after ~300 ms |
| Labels contain HTML | XSS | Text nodes; never `innerHTML` |
| Input blurs on mousedown | Click does nothing | `preventDefault` on `mousedown` |
| IME composition (CJK) | Enter picks mid-word | Ignore keys while `isComposing` |
| Hot prefixes like "a" | Origin overload | CDN caching, in-memory trie |

## Trade-offs

| Choice | Gain | Cost |
|---|---|---|
| Longer debounce | Fewer requests | Feels slower |
| Debounce, not throttle | Fewest requests | Nothing updates mid-burst |
| Client cache | Instant backspace | Stale suggestions |
| Trie, not a search engine | Fast, no extra system | Exact prefixes only |

## Follow-up questions

<FollowUps>
  <FollowUp q="How do you highlight the matched text safely?">
    Split on an escaped regex, wrap matches in `<mark>`, and let React escape every piece. Never use `dangerouslySetInnerHTML`.
  </FollowUp>
  <FollowUp q="What happens on a slow or offline network?">
    Show cached results at once, show loading only after a short delay, and fail quietly.
  </FollowUp>
  <FollowUp q="How would you rank suggestions?">
    On the server: prefix matches first, then popularity, recency and the user's history. Precompute the top 8 per prefix offline.
  </FollowUp>
  <FollowUp q="What changes on mobile?">
    Bigger touch targets, a Search key on the keyboard, no hover-only UI, and a slightly longer debounce.
  </FollowUp>
  <FollowUp q="How do you show recent searches?">
    On focus with an empty box, list recents from localStorage, each removable. Save real searches only, capped at about 10.
  </FollowUp>
  <FollowUp q="The list is local: 5,000 countries. What changes?">
    Filter in memory on every key, with no debounce. 5,000 comparisons take well under a millisecond.
  </FollowUp>
</FollowUps>
