<TLDR>
Debounce input (~250 ms), abort the stale request on every change, and cache per query in a small LRU with a TTL so backspace is instant. Render an accessible WAI-ARIA combobox with `<mark>` highlights; a server-side top-K trie answers in O(prefix length) behind a CDN.
</TLDR>

## Clarifying questions

Each answer changes the design.

- **Source?** A remote API (debounce, abort, cache) or a small local list (filter on every keystroke, no network).
- **Count and shape?** About 8 strings or rich items (icon, avatar); hundreds need virtualization.
- **Search box or form field?** Search runs the typed text on Enter; a form field (pick a country) must hold an option.
- **Keyboard, screen readers, mobile?** Always yes: an ARIA combobox, touch targets, IME composition for Chinese, Japanese and Korean.
- **Recents or personalisation?** Recents live on the client; personal ranking on the server.

### Architecture

In the component tree, play **Typing**, **Arrow keys and Enter** and **Click an option**.

<FlowDiagram spec={componentTree} />

- `Typeahead`: UI state only (open, active option).
- `useTypeahead`: data (query, debounce timer, AbortController, LRU cache).
- `fetchSuggestions(q, signal)`: a prop, so any backend or test fake plugs in.
- `Highlight`: text pieces and `<mark>` elements, never HTML strings.

### Data model

```js
// Data state, in the hook
{ query: 'rea', status: 'idle' | 'loading' | 'success' | 'error', items: [{ id, label }] }

// UI state, in the component
{ open: true, active: -1 }          // -1 = no option highlighted yet

// Client cache: Map<query, { items, at }>, capped at 100 entries, 60 s TTL.
// Map keeps insertion order, so delete + set on access makes the first key the least recently used.
```

### Interface

The code shows the component, its hook and the CDN-cacheable suggest API. Add a `type` per item (query, user, product) if kinds mix.

```jsx
<Typeahead fetchSuggestions={(q, signal) => api.suggest(q, signal)} onSelect={item => runSearch(item.label)} label="Search" />

useTypeahead(fetchSuggestions, { delay: 250, minChars: 2, ttlMs: 60_000, maxEntries: 100 })
// → { query, setQuery, status, items }
```

```http
GET /api/suggest?q=rea&limit=8

200 OK
Cache-Control: public, max-age=300, stale-while-revalidate=3600

{ "q": "rea", "items": [{ "id": "rea:0", "label": "react" }, { "id": "rea:1", "label": "react native" }] }
```

### Optimizations

- **Fewer requests:** a 2-character minimum and 250 ms debounce; the server lowercases and trims prefixes so users share CDN cache keys.
- **Fast:** abort stale requests, LRU for backspace, trending suggestions prefetched on focus, ~8 items so no virtualization.
- **No clashes:** `autoComplete="off"` hides the browser's dropdown; `enterKeyHint="search"` adds a mobile Search key.
- **IME and screen readers:** skip keys while `isComposing`, query after `compositionend`; a polite live region says "8 suggestions" or "Suggestions unavailable".

## Step-by-step answer

<Steps>
  <Step title="Clarify the scope">
    Confirm the scope, then state the plan: "a hook for data, a combobox for the UI, a prefix index on the server."
  </Step>
  <Step title="Debounce the input">
    Wait ~250 ms after the last keystroke and skip queries under 2 characters: a fast "react" sends 1 request, not one per key. In React it's a `setTimeout` in an effect whose cleanup clears it.
  </Step>
  <Step title="Fix the race">
    Pause twice and the older request may answer last. Abort it in the effect cleanup, and check the signal too, since some servers ignore aborts:

```js
const items = await load(q, ctrl.signal);
if (ctrl.signal.aborted) return;                   // a newer query took over
// …
return () => { clearTimeout(timer); ctrl.abort(); };   // cleanup: cancel the wait and the request
```
  </Step>
  <Step title="Cache results">
    A Map of query to `{ items, at }`, re-inserted on write so its order is LRU order; evict past 100 entries, ignore entries older than 60 s. Check it **before** the timer starts, so backspace is instant. More in the [caching lesson](/learn/caching).
  </Step>
  <Step title="Render an accessible combobox">
    The input gets `role="combobox"`, `aria-expanded`, `aria-controls` (listbox id) and `aria-activedescendant` (active option id); the `ul` is `role="listbox"`, each `li` a `role="option"` with `aria-selected`. Arrows move, Enter selects, Escape closes; focus never leaves the input. `preventDefault` on an option's `mousedown` stops the blur that would close the list before the click lands.
  </Step>
  <Step title="Highlight safely">
    Split the label on the regex-escaped query with a capture group, and wrap the odd pieces (the matches) in `<mark>`. React escapes all text, so a label like `<img onerror=…>` stays text.

```js
'React Native'.split(/(re)/gi)    // ['', 'Re', 'act Native']: matches land at odd indexes
```
  </Step>
  <Step title="Cover the states">
    **Loading:** keep the old items; spinner only after ~300 ms. **Empty:** "No suggestions". **Error:** quiet, and typing and plain search still work. The live region announces each.
  </Step>
  <Step title="Design the backend">
    A trie from query logs, every node holding its top-K completions (K = 8): lookup is O(prefix length), no subtree search. Rebuild offline and swap atomically. `Cache-Control: public` lets the CDN absorb hot short prefixes like "a" and "re". Fuzzy matching or huge catalogs: a search engine's completion suggester.
  </Step>
</Steps>

<Callout kind="interview">
"Debounce cuts how many requests I send, not their order: two can still be in flight. So each query gets an AbortController that the next keystroke aborts, and I ignore any result whose signal was aborted."
</Callout>

- `useTypeahead.test.jsx`: fake timers prove 3 quick keystrokes send 1 request, for the latest query; sibling tests cover cache, abort, trie, highlighting and keyboard.

## Failure modes

| What breaks | Effect | Mitigation |
|---|---|---|
| Responses arrive out of order | An old query's results flash | Abort; ignore aborted results |
| API down | No suggestions | Error in the live region; typing and search still work |
| Slow network | Feels laggy | Keep previous items; spinner after ~300 ms; cache |
| Labels contain HTML | XSS | React text nodes; never `innerHTML` |
| Input blurs on mousedown | Clicking an option does nothing | `preventDefault` on the option's `mousedown` |
| IME composition (CJK) | Enter picks an option mid-word | Ignore keys while `isComposing` |
| Hot prefixes like "a" | Origin overload at peak | Normalised keys, CDN caching, in-memory trie |

## Trade-offs

| Choice | Pros | Cons | Choose when |
|---|---|---|---|
| Longer vs shorter debounce | Fewer requests | Feels slower | 200–300 ms is the sweet spot |
| Client cache TTL | Instant backspace | Stale suggestions | 30–120 s for suggestions |
| Client vs server ranking | Works offline | No global popularity | Server, almost always |
| Debounce vs throttle | Debounce: fewest requests | Nothing updates mid-burst | Debounce by default; throttle for mid-typing results |
| Trie vs search engine | O(prefix) lookups, no extra infra | Exact prefixes only; rebuild to update | Trie for known vocabulary; engine for fuzzy |

## Follow-up questions

<FollowUps>
  <FollowUp q="How do you highlight the matched text safely?">
    Split on an escaped, capture-group regex, wrap the matches in `<mark>` and let React escape every piece, as `Highlight.jsx` does. Never feed an HTML string to `dangerouslySetInnerHTML`.
  </FollowUp>
  <FollowUp q="What happens on a slow or offline network?">
    Serve cached results at once, show loading only after a short delay, and fail quietly with "Suggestions unavailable". Skip requests while offline (the `online` and `offline` events).
  </FollowUp>
  <FollowUp q="How would you rank suggestions?">
    On the server: prefix before substring matches, then popularity, recency and the user's history. Precompute top-K per prefix offline and blend in a few personal results per request.
  </FollowUp>
  <FollowUp q="What changes on mobile?">
    Bigger touch targets, `enterKeyHint="search"`, no hover-only UI, a full-screen results sheet, and a slightly longer debounce: typing on glass is slower and burstier.
  </FollowUp>
  <FollowUp q="How do you show recent searches?">
    On focus with an empty query, list recent searches from localStorage under their own heading, each removable. Save on real searches, de-duplicated and capped at about 10.
  </FollowUp>
  <FollowUp q="The list is local: 5,000 countries or contacts. What changes?">
    Filter in memory on every keystroke with no debounce: 5,000 string comparisons take well under a millisecond. Virtualize if hundreds can show, or keep the top 8.
  </FollowUp>
</FollowUps>
