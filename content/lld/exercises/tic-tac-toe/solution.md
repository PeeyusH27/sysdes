This is the "thinking in objects" exercise in miniature: the rules are easy, so the grade is on who owns what.

1. **Find the nouns and verbs.** Nouns: game, board, player, mark. Verbs: move, check for a win, report the winner. The grid and "does this line belong to one player" are about cells, so they belong together in `Board`. Whose turn it is and whether the game is over are about the match, so they belong in `Game`. A `Player` class would only hold a string here, so the mark itself (`"X"` or `"O"`) is enough: do not add a class that carries no behaviour.
2. **Keep `Game.move` a short decision list.** It checks, in the order the statement gives, game over, wrong turn, bad cell, then asks the board to place the mark. Rejected moves return before anything changes, which is why they cannot use up a turn.
3. **Make the win check O(1) with counters.** After each move only one row, one column and at most two diagonals can have changed. Keep a total for each: `rows[r]`, `cols[c]`, `diag` and `anti`, adding +1 for `"X"` and -1 for `"O"`. A line is complete exactly when the absolute value of its total is `n`, because a mixed line can never reach `n` in absolute value. The cell is on the main diagonal when `row === col` and on the anti-diagonal when `row + col === n - 1`.
4. **Track the filled count instead of scanning for a draw.** `filled === n * n` after a move that did not win means a draw. Check the win first, so a last move that completes a line is a win.
5. **Hide the data.** `board()` hands out a copy of the grid, and `Board.place` is the only code that writes a cell, so the counters and the grid cannot drift apart.

Where the design bends: a different winning length (connect-four style) or a rectangular board changes `Board` alone, and `Game` does not notice. Three players would replace the `turn` toggle with a list of players and give each player its own weight or counter map, which is a change in `Game`'s turn handling and in the counter representation, not a rewrite. A computer opponent is another class that reads `board()` and calls `move`.

Cost: O(1) time per move and O(n^2) space for the grid plus O(n) for the counters. The naive version, which scans the row, the column and the diagonals after every move, is O(n) per move and still fine for 3 by 3, but the counters are the version an interviewer is hoping to hear as the follow-up.
